# 创作方法与任务选择（2026-10-26）

## 边界

保持唯一 Scene v2、统一 Command 执行、来源/物理尺寸/裁片占用和真实 Canvas 预览。创作方法是指导信息，不增加一种作品格式，也不生成固定坐标模板。

`src/creation-guidance.js` 同时供搭配页、网页 AI 动态指导、应用内 AI 和生图提示使用。它根据现有风格、用途、文字策略及本次候选材料选择方法；用户无需新增配置。主素材、普通胶带/印章、数字预设分别计数，避免 27 个辅助预设让一张照片被判断成“主素材丰富”。分类只是线索，实际视觉重量仍需查看原图和毫米尺寸。

## 阅读与执行

1. `self-test` 检查环境；`brief` 返回 TASK 的任务、事实、选择优先级、尺寸、图片路径与方法选择，不展开来源快照。
2. 动态 `design/GUIDE.md` 说明本次需求；共用 `design/SKILL.md` 说明图文共同构图与视觉迭代。
3. `guide` 列目录；`guide tape stamps` 或 `guide 美式拼贴` 只返回需要的方法与可执行命令名。精确字段仍用 `describe`，不重复维护另一套参数 Schema。
4. 完整初稿 → apply → 真实 preview → 看图找具体原因 → 有必要的修订 → pack。不是强制粗排、强制三候选或强制工艺数量。

`brief`、`guide` 只读，不改 Scene。非法专题返回 `GUIDE_TOPIC_UNKNOWN`，不猜文件路径。移除无调用方的旧 instructions/plan 文档导出，避免维护者再次引用过时协议和组坐标说明。

离线 ZIP 先采用本地 CLI：网页 AI 环境拿到 ZIP 即可操作，不需要常驻服务或连接用户数据库。将来如宿主有稳定 MCP，可作为同一执行器的薄传输层；当前没有新增 MCP 服务。应用内模型的 native-tools 与 JSON tools 均使用统一 Command 会话；旧 direct-page 执行分支已移除。传输一致不等于所有页面入口、真实素材和高级能力已完成验收，已验证范围见后文。

## 实际试作暴露的执行问题

- `material.split`/实体裁切替换原图层时，沿用原层级与组归属，避免加工后的背景跳到文字上方。保留原有兄弟图层 zIndex，避免误触锁定或用户编辑保护；覆盖根级和旋转组回归。
- Scene 渲染器把已有画布工厂传给素材绘制、胶带取样与轴向旋转。Node 与网页继续使用同一算法，不使用 document 全局垫片或替代图片。真实胶带 Command→PNG→pack 通过，横纵轴像素回归验证非透明源像素被正确绘制。
- Schema 错误优先报告具体深层字段，路径内不支持的 strokeWidth 不再误报另一个分支的 viewBox。严格字段校验保留。
- 仅预设试作发现，素材与图形的底层默认 zIndex 不同，后添加的贴纸被先前的色块盖住。统一 Command 的新建节点现在按命令顺序放在同级最前方，修改保留原层序，显式 order 控制先后。只改新节点，不重新编号锁定兄弟；实体裁切替换仍保留原层级。

## 共用执行基础（进行中）

`creation-transaction.js` 负责同一 Scene 文档的 SHA-256 版本、原子 Command 批次和幂等回执，离线 CLI 已直接使用它；文件锁与可靠落盘仍由 CLI 宿主负责。`creation-document.js` 提供应用内任务冻结入口，与 ZIP 共用来源构造。随后应用内模型回合与视觉复核已切换到同一事务模块；宿主仍负责可靠暂存、账号/素材版本保护与取消控制。

默认 `inspect` 只输出图层标识、页面毫米坐标、父组、文字、图形参数及必要样式；`--full` 保留完整 Scene 查询。简略坐标只用于阅读，保留五位小数，不改权威 Scene。局部原生字段与世界坐标明确分开；位置修改应使用 Command 的 `place.reference`。

局部组合蒙版的保留面积校验与真实渲染都使用相同空间：带局部矩阵的组以居中的 `layoutBox` 为蒙版范围。嵌套隔离层按页面坐标绘制，避免负局部坐标被中间画布裁掉。直接 Scene 修改也不能通过移动祖先来绕过锁定子层。相关测试包含真实 Canvas 像素、重开后检查、事务回放与真实 ZIP apply/preview/pack。

## 应用内统一 Command（2026-10-26）

- `creation-agent-session.js` 只做模型网关：`creation_apply`、`creation_help`、`creation_guide`、`creation_inspect`、`inspect_materials`、`creation_finish`。生成、加工和局部修改都提交协议 2 Command；原来的整页输出/旧工具协议不再作为模型的第二入口。内部已验证的素材算法继续复用。
- 每个运行只有一个冻结来源的权威文档。每个 Command 批次整体提交或整体回滚；同一事务重试返回回执；版本冲突返回当前版本。宿主仅把 Scene 及创作状态交给原有可靠检查点，不另存一份平行作品。
- 简略检查区分组内字段与页面毫米坐标，保留图形高级参数、遮罩和来源别名。模型可按对象查询完整信息，不能通过观察接口读取未授权素材。
- 视觉复核使用同一个会话与事务 reducer 修改，修改后先可靠暂存，再重新渲染。最终渲染失败不报告完成。只读帮助和检查回合不重绘相同 Scene；所有模型请求共享原有预算。
- 浏览器字形镂空按需加载内置 Ma Shan Zheng，不接受模型字体路径或网址；其他字体可提供显式 region 轮廓。字体只用于生成几何，不塞进 Scene。带封闭字腔、会产生分离纸片的镂空仍由物理校验拒绝，不伪造成功。
- 实际浏览器发现并修复两处集成问题：OpenType ESM 导入与 Node 不同；组内素材的世界坐标代理不能用对象引用相等来判断素材类型。必用素材可见性也改为世界坐标检查。

## 提示收敛与第四轮真实素材试作

- 应用内首轮只传一次当前 Scene，使用会话的准确版本。删去无调用方的旧 plan/observations 工艺指导，物理约束留在共同规则，素材关系与文字策略留在本次任务，具体工艺按需 `creation_guide` 查询。完整能力没有用删 Schema 的方式压缩。

### 2026-10-26：让组合关系可在界面接续编辑

教程中的“照片旁注、局部高亮、装饰呼应”需要可持续的对象关系。新增叶对象“跟随对象”面板，通过共享 `applySceneNodeChange` / 受保护的解除入口编辑现有 layoutConstraint；保留原生 Scene 单一事实源、锁定规则、实物比例及隔离编辑会话。布局面板不新增创作协议。

原生 UUID 与公共 Command 编号验证已统一；浏览器拖动提交也会更新被求解移动的跟随对象。布局关系的存在不能当作作品审美已经达标，后续仍需作品对比与多题材验证。


### 2026-10-26：组合与子对象的一次编辑会话

选中组合能编辑整体外观、进入子对象修改并返回；全部修改仍只作用于会话中的同一 Scene，完成时一次提交，放弃则不改变保存作品。没有复制成平面图片或引入组合专用持久格式。此入口让 AI 生成的标题/拼贴组可以继续人工细修。

新发现的后续整合项：`groupSceneLayers` 的人工默认和 `mergeSceneLasso` 仍创建未定义局部定位框的普通组合；AI `group.compose` 创建空间组。下一步需统一创建时的局部坐标与稳定定位框，检查父级参照重绑定和遮挡顺序，不能简单打开 spatial 标志后算作完成。

### 编辑器接续：2026-10-26 跨组关系

空间组当前拥有稳定父坐标定位框；移动、编组和解组时，parent 约束重绑定保留当前外观，再跟随新父组。共用 Scene 结构操作完成这一步，AI 无需生成补偿坐标或辅助脚本。纸张转换处理组的局部坐标，属性预览接受世界坐标投影而不深拷贝 Proxy。
