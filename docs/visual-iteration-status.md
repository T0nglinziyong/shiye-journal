# Bounded guidance and real visual iteration

Base: a89707ad (test). Branch: refine/visual-creation-loop-20261022.

## What changed

The editable export now has one task-dependent GUIDE, one SKILL, an on-demand PLAYBOOK and a PNG REVIEW. CRAFT_GUIDE is a short routing index, not another copy of the method. GRAPHICS, LETTERING and registry-generated RECIPES remain optional technical references. TASK points to creativeBriefRef instead of duplicating all prose. Unused legacy workbench instruction strings are removed, and old native-field wording no longer leaks into current editable tasks. Content policy, explicit no-text mode, user prose, processing constraints and spread boundaries remain authoritative.

Review runs after primary masses and readable content, not only after embellishing a finished layout. Each review names a visible area, defect, action and expected change. Rich purposeful details remain encouraged; count/coverage is not an aesthetic pass. Printed titles and table lines count as occupied content. Layer order is explicit, not inferred from command order.

## Actual experiment, not only a synthetic code test

Five readable original tutorial clips were inspected through sampled frames and visible subtitles; a claimed sixth could not be located. No full audio transcription was made. The provided handmade photo and recent AI PNG were comparison references, not executable ground truth.

- R1: fresh exported eight-material B6 spread, structure and detail Commands executed and actual PNGs viewed. Text roles improved, but orphan punctuation, an untargeted ring and misplaced highlights remained. Visual review failed.
- R2: revised bounded guidance, another fresh eight-material task; source image bytes, physical sizes, required set and policy unchanged. Four real previews: structure, detail, physical partition revision, then layer-order correction. A real paper partition created backing and a narrow strip without duplicate consumption. Final review accepted the corrected sample; this is a subjective sample judgment, not a global aesthetic score.
- R3: explicit two-material transfer task on the same page dimensions. Typography and digital geometry provide the main layout. An initial preflight exposed real assets appearing under later-sorted backgrounds; guidance replaced one sentence with explicit order semantics. Fresh task then produced structure/detail/revision PNGs. Highlighter width/position and an unnecessary curve were corrected after viewing.
- Final exporter replay: both accepted designs recreated from empty current packages using their saved operations. PNG SHA256 exactly matched the reviewed R2/R3 images. Current runtime check/apply/preview/review/pack succeeded. No alternate renderer or hand-edited Scene was used.

Commands, images, task invariants, guide hashes and execution logs are retained in private user deliverables, not committed. No original videos, private material images, font binaries or personal work is added to the repository.

## Size control

Measured Unicode characters for the same default eight-material task (not model tokens):

| Route | Baseline | Final |
|---|---:|---:|
| START_HERE + task GUIDE + SKILL | 9,267 | 2,897 |
| Above plus CRAFT_GUIDE + PLAYBOOK + REVIEW | 15,820 | 4,489 |
| Duplicated TASK.creativeBrief prose | 4,528 | 0 |

Method/review prose decreased 71.6%. R1/R2/R3 drafts stayed around 4.4k characters; small fixes replaced ineffective text rather than creating more manuals. Tests cap each document, first read and the combined method route, validate current public operation vocabulary, and verify that explicit long user input is not truncated by these default budgets.

## Evidence limits

One assistant authored and reviewed all runs after seeing references: this is exploratory iteration, not independent/blinded A/B, and does not establish that other webpage-AI sessions will reliably improve. The same available artistic font was used in the local rounds, but the earlier user screenshot may have used a different font environment. Font change is a confound in that comparison. Material source pixels are low resolution and are not regenerated. Sample-level review remains subjective. Budget and rendering tests cannot measure beauty.

Repeat future experiments with a fresh source package and the same task constraints; retain actual PNGs and localized review decisions. Do not add private examples or another generic rule for every failure. Change one layer of guidance at a time, revise under the budgets, and use an explicit sparse-material or different-aspect task to check for overfitting.
