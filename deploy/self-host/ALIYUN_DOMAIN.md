# 阿里云域名 `shiyejournal.vip` 接入拾页

注册并完成持有者实名认证，只说明域名属于你；DNS、服务器、HTTPS 和网站是后续独立步骤。此文件使用 **2026-09-29 用户提供的域名**，取代旧模板中的 `shiyejounery.top`。

## 首选：4090 电脑直接承载网站和数据

1. 先在 Ubuntu 4090 上确认公网入口：路由器 WAN IPv4 与外网查询的公网 IPv4 是否一致；若路由器拿到 `10.x`、`100.64.x`、`172.16–31.x` 或 `192.168.x` 等私有/共享地址，普通端口转发无法让公网访问。只有 IPv6 时需确保公网 IPv6、运营商入站访问、路由器及防火墙配置均可用。DNS 不能解决 CGNAT。
2. 在阿里云 [域名解析](https://dnsnext.console.aliyun.com/authoritative/domains/shiyejournal.vip) 中“添加记录”：主机记录 `@`，类型 `A`，记录值填 **4090 所在网络的真实公网 IPv4**，解析线路“默认”，TTL 可保持 10 分钟。若确实拥有可入站的公网 IPv6，可另加 `@` 的 `AAAA`，记录值填真实公网 IPv6。不要填局域网 `192.168.*` 或 Node 的 `127.0.0.1`。暂不必添加 `www`，本站模板只配置根域名。
3. 路由器将 TCP 80 和 443 转发到 4090 的局域网 IP；Ubuntu 防火墙允许这两个端口。Node 只监听 `127.0.0.1:4173`，不可把 4173 对外开放。
4. 在 4090 上按同目录 `README.md` 安装 Node、Caddy、systemd 服务；`shiye.env` 需填 `SHIYE_PUBLIC_ORIGIN=https://shiyejournal.vip` 和独立随机令牌，`Caddyfile` 已配置新域名。Caddy 会在 DNS 和公网端口都就绪后申请 HTTPS 证书。
5. 从手机蜂窝网络测试 `https://shiyejournal.vip/api/health` 和首页（不要只在家庭 Wi-Fi 内测）。首页应要求服务器访问令牌，登录后在“数据与诊断”核对唯一数据源。再从旧 Vercel 网址的原设备导出 `.shiyepwa` 备份，在新域名恢复。

| 阿里云记录 | 主机记录 | 类型 | 记录值 |
|---|---|---|---|
| 根域名 | `@` | `A` | 4090 网络的真实公网 IPv4，确定后填写 |
| 可选 IPv6 | `@` | `AAAA` | 可从公网连入的真实 IPv6，确定后填写 |

## 如果 4090 没有可入站公网地址

可以暂时把 `shiyejournal.vip` 绑定到 Vercel 项目，先让域名访问**旧 Vercel 站点**。先在 Vercel 项目 Settings → Domains 添加域名，按 Vercel 当时为该项目显示的记录值在阿里云添加相应 A/CNAME；不能凭本文件填写一组过期或不匹配的值。这样只改变网站入口，浏览器数据仍按域名隔离，4090 也不会自动变成唯一数据源。若以后有可信隧道或公网反向代理，可再将域名接回 4090；迁移前导出备份。

不要同时把同一根域名的记录指向 4090 和 Vercel，否则访问可能落到不同站点。选定入口后再设置 DNS。内地服务器的网站备案要求与服务器所在地、接入方式有关；域名实名认证不等于网站备案。
