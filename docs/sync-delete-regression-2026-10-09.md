# 跨设备删除与全页面同步复核（2026-10-09）

## 根因与证据

Supabase 的近期修订日志包含真实删除：例如 1251/1253/1254 修订中有 `projects:delete` 与对应 `trash:put`，1255–1259 有 `trash:delete`。因此并非数据库不支持删除事务。

主要可见性错误：`view-update-policy.js` 曾在选择模式存在时阻止后台重绘。远端版本已经进入 `state`，但本机旧卡片仍显示，用户会误以为删除没有同步。

另外，`shiye-journal` 正式 Vercel 项目目前缺少 `VITE_SHIYE_SUPABASE_URL` / COS 环境配置（项目级变量计数为 0），因此正式站与测试站的存储模式可能不同。**不能把正式站未配置云端服务解释为测试分支代码删除失败。**

## 同步规则

- 持久化对象：`assets / series / projects / trash / blobs / meta`，修改经版本化云端事务与账号隔离 outbox 上传。
- 删除：素材、作品入最近删除由 `原记录 delete + trash put` 同一原子事务完成；恢复由 `trash delete + 原记录 put` 完成；彻底删除由 `trash delete` 完成。
- 另一设备：前台约每 15 秒检查云端修订；选择模式也允许安全刷新并移除过期卡片。相同浏览器里的其他标签页会接收已提交变更的广播。
- 搭配、导入：不进行**后台拉取导致的页面重绘**，以免丢失当前暂存编辑；退出这些页面立即检查云端。**导入已确认并保存的作品／素材／快照仍必须上传**；搭配产生的最终作品亦必须持久保存，不能丢失。
- 活跃创作编辑器：云端修改会下载进状态，但不重建画布、擦除笔迹或抢占焦点。如果当前作品已在另一设备删除，提示用户先导出可编辑 ZIP，并避免“完成／返回”无提示地自动复活该作品。
- 设置：非敏感 UI/识别偏好保存在账号隔离的 `meta` 中以便跨设备同步；AI API 密钥与凭据只在本机，不放入云端。设置表单编辑期间不强制重绘，退出表单才采用较新的云端偏好。

## 测试

- 独立执行 `view-update-policy` 3/3、`cloud-delta` 7/7、`sync-last-write` 3/3、`cloud-preferences` 2/2。
- 使用真实 `createCloudStore` 与真实 `createProjectSync` 在隔离 V8 模拟：素材删除、作品删除、最近删除彻底删除、删除前已暂存作品四条路径；四条均产生正确的云端操作、清空已确认 outbox，且不存在删除后自动保存导致的重新 `put`。
- 变更过的脚本与同步核心模块均通过 JavaScript 语法检查。
- GitHub Actions 额度耗尽：没有将以上模拟当成真实浏览器/Safari/双设备验收。仍需用两台设备互相删除和恢复，检查约 15 秒的拉取、窗口切换和离线重试。

## 发布要求

`test` 修复部署 READY 不代表 `main` 正式站已具备云端配置。发布到 `main` 前先确认正式站使用哪个 Supabase 项目/COS 桶，设置所需生产环境变量；否则正式站仍会使用本机数据。不得直接复制私有凭据到源码或 CI 日志。
