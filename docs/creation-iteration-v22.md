# 创作包 v22 实验：减少模板诱导，保留真实约束

2026-10-24，使用 GPT-6 Astra / high 独立子代理。私人原图、作品与完整实验记录留在本机交付目录，不提交仓库。

## 根因与取舍

上一轮把丰富度逐渐收缩成“首批画一个主图形，再增加它的尺度”。两套候选仍是完整矩形和同一条路径，只变坐标。增加路径工具没有改变材料职责；几何提示消失也没有证明画面成熟。

本轮区分三个问题：结构是否成立、内容是否值得读、局部执行是否准确。每次修订记录问题、原因、改变和实图结果；不把最新版本默认当最好。五件素材的结构 B 确实不对称，却使正文窄碎、局部散开，独立评审选择保留 A。

## 实际调整

- START_HERE 与 REVIEW 合计由 16,191 字节缩至约 6,220 字节；删除主路径强制、每轮必须双候选与重复的图形配额暗示。
- 不变的工作流仍是任务/素材 → Commands → 唯一 Scene → 真实 Canvas PNG → 同源交付。没有新中间格式或并行状态。
- 首稿包含实际文字和关键细节，方向明确直接完成；只有真正的结构选择才预览候选。
- `preview` 默认只返回图片路径、指纹、耗时和诊断文件路径。完整几何/像素报告仍存文件，`--full` 可直接查询；不让大量近似指标占据每轮上下文。
- `describe` 支持一次查询多个操作，单项返回不变。
- `review` 记录创作者判断，不用“有无图形节点”冒充丰富度门槛。实际 PNG、来源、物理尺寸和 pack 重渲染校验保持。
- TASK 每件素材直接标记 required/preferred/available，必选执行约束不变；其余允许取舍并记录原因。
- 动态指导由同一函数生成，网页导出与实材再生成包共用。高级工艺和全部操作保留。
- 两个实验都踩到裁切后仍按原框定位的问题：补充 material.cut 帮助，明确此合同。没有擅自改变锚点语义，也没有宣称已实现可见轮廓定位。

## 已验证与边界

统一 commands 的真实裁片、开窗/穿插、余料、事务冲突、必选素材、Canvas 预览和导入交付由现有端到端测试覆盖。新增验证覆盖短预览与完整报告同源、批量 describe 与单项一致、显式素材优先级及自评不冒充硬性美学判断。

没有用图形数量、覆盖率或自评 pass 宣称审美验收。当前已提升内容与速度，手作穿插的稳定性、字体变化和不同主题的长期多样性仍需更多样本；本轮三组不证明已达到所有人类参考的精细程度。裁切可见边界定位及环境依赖安装仍有明确成本。

## 参考校准对照

八件 A 的结构 B 另花 1分55秒（含一次裁切定位纠错），虽然文字舒展、印刷字减重，却增加大空白、破坏局部连接，已记录 fail，不选为更好版本。

因此停止沿 B 微调，另起 GPT-6 Astra/high 独立代理，实际观看用户人类手帐参考后创作 C。首图约2分03秒。独立评审明确优先 C：文字既进入印刷卡内部空角，也形成舒适的纸面书写块；纽扣与“小门”、兔子与“批准”、纸条与清单各自形成不同阅读关系。最后只修卡内字与页脚边距。

这次结果支持视觉校准的价值，不能证明纯文字指导已经具备同等稳定性，也不能把相同材料的近似风格当长期多样性证据。本轮未将用户私人参考图注入所有用户创作包。

独立代码审查还发现 `preview --full --commands ...` 的 flag 顺序会静默渲染正式 Scene。已先规范选项再解析命令参数，补两种顺序及缺失路径测试；11 项真实包回归通过，候选仍不写正式 Scene 或预览。

C 最终实际 PNG 已检查，完成耗时4分06秒，无工具执行报错。仍有大印刷卡偏重、字形行列较规整的问题；作为本轮八件交付样本保留，不宣称与人类参考完全等效。
