# 服务器创作 Harness

状态：SQL、云函数与计算服务器已部署；App 已接入并在真实 CloudBase 账号验收，静态站发布另核对准确 SHA。

## 运行合同

手机提交当前方向、素材 ID、页面设置和 Scene，不传素材图片；4090 从 CloudBase 读取已同步的账号素材及私有图片，在服务器生成创作用 PNG。CloudBase 验证账号、冻结本次输入并记录任务。现有 `shiye-job` MQTT 唤醒计算服务器。模型 API 使用 DeepSeek Flash 思考模式；CPU 运行编排与 Canvas 渲染，GPU 可供图像工具使用。关闭手机不终止任务。任务状态、作品、检查点和预览以 CloudBase 为准，MQTT 只发送任务 ID 和修订通知。

新任务统一使用 LangGraph 1.7.5。Pi Agent Core 仅保留用于恢复已经写入 Pi 检查点的任务，以及本机对照实验；旧环境变量 `SHIYE_CREATIVE_RUNTIME=pi` 不再选择新任务运行时。Pi 试验中有效的工具合同统一、坏 JSON 工具调用恢复、压缩历史时保留创作决定和按需重看画面，都沿用或迁入 LangGraph。后台开局只加载核心 Skill 目录；定方向阶段给主题、配色与构图线索，打底构图阶段给少量匹配模板和案例参考，装饰书写阶段才自动提供可执行的标题、配色与局部点缀方法卡。其他教程按需读取，方法摘要写入检查点。首轮将全部授权素材排成一张稳定编号总图；普通回合保留稳定历史前缀；仅在集中压缩时移除较早回合，原始总图保持稳定，需要时也可用 `workspace_view({id:"source"})` 重看，局部细节用 `inspect_materials`。默认有创作区和暂存区，可按需创建独立试摆空间；编辑后重新捕获变化空间；每轮请求末尾提供各空间最新匹配版本图和当前完整 Scene，清空的空间发送状态。旧自动画面不进入模型历史。不存在生成整页位图再冒充可编辑作品的路径。

2026-11-23 对教程入口收拢：活跃 Skill 从 17 个收为 8 个，方法库从 84 个独立 ID 精简为 30 个可调用方法。17 个单步图形、图案和普通字效由基础命令承担；13 个固定偏移的素材布局配方移除，构图改由模型看真实画面后用基础摆放与图层命令完成；其余相近效果以 24 个 `parameters.variant` 选项保留在对应方法里。各专题 Skill 正文直接说明选法，`detail` 返回可选键和准确参数；开窗、穿插、轨迹撕纸、胶片组等复杂封装继续保留。其他九组历史风格笔记移入 `creative-agent/research/`，仅供维护者查阅。三篇最长的教程把来源分析留在同一目录，Agent 使用短正文。开局仅给 8 个专题目录；根据实际 Scene 同时提示相关专题的用途和 `read_skill` 入口，允许同轮读取多个专题，不自动注入整篇教程。模型主动读取时，`methods` 每页最多八个紧凑摘要，`detail` 才给精确参数和单张示意图。图形、普通字效直接用基础命令。真实对照表明自动注入完整专题使轮次与 token 上升，画面也未改善，因此取消这种注入。对照试验可用 `SHIYE_CREATIVE_THINKING_POLICY=low|high|adaptive`，生产默认改为 `low`，`adaptive` 和 `high` 保留为显式实验选项。正常主请求启用思考；长响应超时后重试改为关闭思考，避免重复等待同一长推演。试验结果以同一素材包、画面质量、工具错误、token 和耗时共同判断。

## 工具与上下文整理（2026-11-23，本地开发）

- **职责分开**：`runtime/tools.mjs` 管工具定义、分组和发现，`agent.mjs` 管执行与渲染，`context.mjs` 管上下文；实际 Command 参数继续由 `src/creation-command-spec.js` 生成。
- **渐进披露**：原入口在分割可用时一次暴露 22 个工具，现在首轮只暴露 11 个常用工具。参考读取、选题、空间、分割和额外审查通过 `creation_help topics:[工具名]` 展开，检索结果的 readWith 也会自动展开对应工具。已展开工具写入检查点，阶段变化不会移除；主运行时不再暴露与 Skill 重复的 creation_guide。模型可见范围不是权限判断，宿主能力与原子校验始终生效。
- **准确合同**：creation_apply 的 op 枚举来自执行注册表，初始帮助保留合法字段名；复杂字段按需读取。Skill 目录同时给名称和用途，detail 可直接读取。重复读方法仍返回完整参数，并刷新示例的事务编号与 Scene 版本；只对重复图像去重。
- **任务优先**：冻结任务中的 intent、styles、purposes、contentPolicy、textPresentation、textMode、用户文字与事实显式送入请求。用户约束优先于教程、案例和自动建议。无文字任务不再推荐标题方法。
- **可回退流程**：首次编辑前保留一段方向记录；试摆、文字、点缀和修订可交错，阶段记录可选。关联操作放在一个原子事务里，依赖查询结果的调用等下一轮再执行。编辑后真实看图再交付。
- **保留视觉证据和决定**：普通回合保留稳定的决定、Skill、工具调用和回执。当前画面/完整 Scene 是可替换尾部，不保留过期快照；检查点保留原始渲染证据供审查与诊断。
- **统一交付检查**：无论内联 review，还是先 creation_review 再 creation_finish，都必须通过当前截图的独立审查（宿主提供 critique 时）。没有新模型回合查看的渲染不能立即交付，Pi 逐工具执行也遵守这一约束。

发现并修正的 Skill 漂移包括：已移除的构图配方仍被描述为可调用、标题示例缺少事务字段、图形教程混用 CLI 的 describe 与不存在的 layer.order、纯拼贴被错误扩展为禁止数字图形。正文讲判断，准确参数和完整示例由运行注册表提供。

本轮本地验证：全量 `npm test` 为 2033 项通过、1 项跳过；补充修正后 83 项定向回归全部通过；`npm run test:ui`（含 7 种视口路由检查）、`npm run build` 和 5 个修改过的 Skill 元数据校验通过。回归覆盖工具发现与恢复、Skill 重读、参数注册表一致性、禁止文字与零素材纪实任务，以及独立审查不可绕过。真实画质仍需同素材、同模型、同时间预算的前后对照，分别记录工具失败次数、轮次、输入输出 token、首稿和末稿；确定性测试不证明审美已改善。

## Pi 创作运行时

Pi 实验入口为 `creative-agent/runtime/pi-agent.mjs`。已经有 Pi 检查点的云任务由 `cloud-job.mjs` 识别后恢复；新任务始终进入 `agent.mjs`。Pi Agent Core 的对话与工具回合实验仍可用本机脚本复现。LangGraph 当前共享同一工具调度、自动渲染、Scene 状态、历史摘要与稳定素材编号图，并对未闭合的工具参数给出简短纠正提示后重试。

2026-11-23 本机真实 DeepSeek、八件真实素材验证：Pi 一次完成 16 轮、417088 ms、725624 输入加输出 token，生成六张可编辑 Scene 预览；另一次 23 轮、约 561 秒后在模型响应超时处失败。对照 LangGraph 同素材已完成任务为 13 轮、341841 ms、约 495668 token。两次 Pi 的初摆有可取之处，但没有证明整体更快或更稳定，故恢复 LangGraph 作为唯一新任务运行时。Pi 中暴露的笔迹单位、虚线属性、文字重排等工具歧义已改进共享合同与 LangGraph 错误提示；保留具体构图经验，不把 Pi 的慢调用和额外上下文转发带回生产。此处为本机对照，不等于手机端验收。

切回后用同八件素材进行 LangGraph 真实复测：16 轮、404590 ms、约 724977 主模型输入加输出 token，成功保存可编辑 Scene，但模型没有主动读取任何 Skill。人工逐张查看发现：初稿的人物与星芒纸接触不够明确，后续为写字将人物撤下；最终画面虽然通过自动审查，却比中间稿更平，作者自评还错误地说人物仍在画面上。因此把当前纸面实物清单和撤下的素材变化送入后续观察，并让独立审查用当前 Scene 清单核对在场对象。该修正有定向测试，尚未有第二轮真实模型画质验收；不能把此次成功交付说成审美通过或达到六分钟目标。

## 数据边界

任务源只读；生成结果作为新的候选版本，不能覆盖任务启动后用户修改的作品。模型只能看到本次授权素材和预设。工具不提供任意 shell、网络地址、SQL 或文件路径。系统预览、最终作品和字体由现行渲染器生成。检查点可含用户文本/素材预览，放在账号私有路径；不会发往第三方监控服务。

运行截止时间从任务入队计算，恢复不重置；每轮调用使用剩余时间。重复通知仅尝试领取同一任务；租约持有者才能更新。确认取消后不再发布完成结果。通知丢失时登录、恢复前台和重连补读 CloudBase。运行中有限进度检查可以服务取消/租约，不恢复空闲数据库扫描。

## 手机与后台

编辑器与搭配页面的纯编辑入口调用 `background-creation-session.js`。它把任务输入先保存到账号隔离的 IndexedDB；任务 JSON 上传、数据库入队及 MQTT 发布成功后才显示已提交。后台使用持久 MQTT 会话，重连只核对未结束任务，不运行空闲扫描。手机离开只卸载观察器；“停止”才写入 CloudBase 取消状态。

同一来源使用原子 Scene 事务，可在一次操作中移动、裁切、排版和调整多层。创建和移动共用 `place.surface`，默认值为 `page`，暂存区为 `tray`，其他 ID 由 `workspace_create` 创建。所有空间共用毫米坐标、旋转、相对锚点和组合；非纸面对象保存在 Scene 中，由组合根节点决定其空间。`creation_undo` 可撤回最近一次成功编辑批次，随后自动重绘。工具参数按需查询；SAM 只返回提议，下一轮看过轮廓后才能真实裁切。前端收到中间图只更新预览；完成结果按原稿快照核验，人工已修改则另存候选，重复通知复用同一收据。

部署使用同一个 `shiye-compute-01` MQTT 客户端。创作有两个后台执行槽，分割保留原有槽；CPU 负责 API 调用和渲染，GPU 只在需要分割时工作。服务重启释放租约，恢复原截止时间和事务收据。

现有每日 03:00 清理任务扩展到创作中间文件，满 24 小时才回收。未接回作品保留最后预览和结果；只有云端作品记录包含完成收据才可回收最后结果。任务索引保留供恢复与诊断。纯绘画和旧混合模式入口代码仍保留，尚未迁入这个后台执行器。

## 当前边界

实体手机锁屏由页面完全卸载与重新打开模拟；未以浏览器视口代替实体 Safari 验收。失败和取消保留云端检查点与最后已发布预览，但当前 UI 尚不提供从任意中间步骤挑选并继续的版本面板。不同风格的模型输出可能仍有留白、阴影或细节需要人工调整；不以模型自审保证每次都满足审美。

## 自动反馈与轮次控制

每批改变 Scene 的事务后，后台自动渲染并提供当前 Scene、必用素材清单、最终提交校验和视觉审查任务。几何检查是程序结果，视觉判断由模型看真实图完成；两者不能混作审美通过。每次编辑后的最新图可以直接用于下一批调整；`creation_review` 可记录单次视觉判断，模型可自行判断是否记录工作重点；`creation_phase` 仅作可选声明，不审批阶段。最终审查中的阻断问题仍需修正。未解决的问题不能在同一画面版本上改口通过。满意时可直接在 `creation_finish.review` 中交付，后台绑定准确预览和 Scene。修改后同轮完成、旧图审阅和未解决问题仍会被拒绝。审查结果和所据画面版本随检查点恢复。

草稿探索仅保留实验代码，当前主创作 Agent 不暴露 `explore_drafts` 和 `select_draft`。实验入口中，多个构图方向都合理时可调用 `explore_drafts`。后台并行运行 2–3 个只拥有 `creation_apply` 的独立子 Agent；每个从相同主 Scene 基线生成一个可编辑候选，渲染真实截图，但不保存为主作品。主 Agent 看过候选图后用 `select_draft` 说明取舍，选中的 Scene 才替换主稿并重新预览审查。候选基线过期、没有有效事务或预览与 Scene 不一致时拒绝采用。小幅修改不启动探索，剩余创作时间不足时也不再开启新分支。

参考知识先使用仓库内唯一版本的模板与技巧目录。`search_references` 按查询词、风格、主题、纸张比例和本次素材适配检索少量候选，返回来源、匹配理由和后续读取工具；`read_template` 或 `read_skill` 才加载完整结构、示意图与调用参数，`creation_recipe` 生成可编辑 Scene。结果同源重复会降权。检索不自动把素材放入页面，模型需对照真实图决定是否采用。当前没有把其他账号的作品、未经核实的网页或向量索引混入参考库。

主 Agent 保留 `direction`、`layout`、`craft`、`review` 四个过程标签，但不强制逐段切换。结构化 `creation_plan` 检查主题依据、颜色来源、多焦点或无单一主角的视觉锚点、布局意图及文字区，成功后进入构图。构图阶段可检索模板与案例、比较草稿、摆底纸与素材簇；模板仅提供元素关系参考，不自动把示例图像放入作品。构图看过数版真实画面后提交阶段检查，把文字与装饰待办带入 `craft`。该阶段自动给少量可执行标题、配色、图形和点缀方法卡，可直接实施，也可继续查阅 Skill；不以技巧数量作为交付门槛。`review` 可继续编辑和看图，最终 `creation_finish.review` 必须绑定最新画面且没有阻断问题。布局、装饰和交付检查另调用一次只看真实截图的独立视觉审查；其明确的阻断问题必须先修改并重新预览，结果与 PNG 指纹一起写入检查点和画质时间线。宿主配置了独立审查但审查不可用时记录故障，并拒绝标记完成。丰富风格允许多个视觉中心、叠放遮挡和充实排版，不设中心主图与固定留白比例。

每次真实渲染都会保存画面 SHA、Scene 版本、缩小像素样本、必用素材覆盖、几何提示和模型审查。相邻版本计算缩小图的平均像素变化，用来定位“修改是否真的改变了画面”，不当作审美评分。人工审阅可按画面 SHA 附加到同一版本；验收报告对比首稿与末稿，并保留每次修改。模型调用、工具执行、渲染各写一条不含图片和密钥的时间线事件，记录阶段、耗时、版本和结果。真实图片与完整检查点仍留在任务私有目录。

CloudBase 完成态任务在账号私有前缀 `reports/evaluation.json` 和 `reports/trace.json` 保存评测与时间线。本机验收脚本在私有输出目录生成同名文件；实际看图后可用 `node scripts/score-creative-harness.mjs <验收目录> <人工审阅 JSON>` 写入按画面 SHA 绑定的 1–5 分与具体说明。模型审阅、几何提示与人工评分分开记录，不能互相冒充。

## 纸张与过程用量（2026-11-24）

### 2026-11-24 缓存与交错调用



同轮可声明多个 read_skill、纸张、标题、基础编辑和查询调用。共享 Scene 的编辑按声明顺序执行；同轮起始版本可用于这些编辑，其他过期版本仍拒绝。每个编辑调用保持事务原子性，失败只回滚本调用，其他独立调用继续；无效 JSON 也返回独立错误，不丢弃整轮。整轮编辑后统一预览。依赖尚未读到的 Skill 参数或分割图的操作仍应等结果，完成交付仍需检查最新预览。中途可通过 before/after 插入纸层，不要求在首批完成打底。

标题入口明确只创建新组；已有标题用 layer.update 修改组或子文字。文字优先使用承载纸面的局部坐标和内边距。专题推荐不再被未读的纸层专题阻挡，纸层、标题、正文和点缀可一起提示。成品审查按用户疏密检查局部层次，不强制字效和装饰数量；审图请求超时与整次任务剩余时间分别处理。


### 2026-11-24 完整请求前缀与历史预算







显式选择 adaptive 实验时，由第一版实质布局的一次性记录控制：有素材时至少放置 min(2, 素材数) 个对象，且双页每页已有素材；零素材时检查新增文字／图形。单纯铺背景纸不会结束有素材任务的 high 阶段。记录生成于真实渲染后，后续退回阶段或补纸不重新升高强度。此判断是可测试的初版构图代理，不是审美合格门槛。



当前快照策略：稳定前缀包含固定说明、任务、初始素材总图、Skill、模型回答与完整 reasoning_content、工具调用和回执，以及变化时追加的工作指导。每轮从模型输入移除旧自动状态/画面快照，在尾部重新提供完整 inspect 图层清单（包含正文、世界坐标、层序树、字号、裁切等）、计划、当前反馈以及各空间最新匹配版本图。readonly 或只改变暂存区也保持当前纸面图可见；关闭的空间不再带图。检查点保存旧渲染证据，模型不再需要拼接增量。

缓存只承诺快照之前的稳定前缀不变；上一轮快照及它之后的最新回答需要重新建立缓存，不能把整份上一请求都算可复用。实际收益以供应商 usage 为准。历史压缩仅作为容量兜底，依据最近输入+输出达到模型窗口60%预留区触发，不因轮数、图片数或 high→low 切换触发；保留最近两轮完整工具周期，最新完整快照会重新注入。DeepSeek Flash窗口依据 https://api-docs.deepseek.com/quick_start/pricing/ 。

## 五个关注阶段（简化）

构思与计划 → 打底与构图 → 标题与内容 → 装饰与点缀 → 最终检查。移除 creation_progress 和问题表，模型不用调用工具维护任务状态。五类方法一次性进入固定说明，每轮尾部提供完整画面、图纸与计划；不按阶段切换方法提示。

阶段完全由模型声明：它可以在同一条工具调用回复首行写 `阶段：装饰与点缀` 等标签，运行时只更新展示记录；不依据计划保存、对象数量、工具成功或轮数自动推进。可回访、可跳过、可交错，不要求额外的状态工具。可选 `creation_phase` 同样只记录模型声明，移除阶段批准与额外审查门槛。最终交付的真实画面校验与独立审查仍保留。

## 2026-11-24 统一工具参数与六分钟目标

- 所有编辑事务支持 `baseSceneRevision:"current"`，绑定本轮模型观察到的 Scene，再顺序执行本轮编辑。显式旧哈希仍会冲突，不绑定无关的新版本。`creation_apply.protocolVersion` 可省略，由运行时写入固定 2。
- 位置、尺寸、外观、层序统一为 `place / size / style / order`；文字统一为 `content`。纸张颜色使用 `style.fill`、印纹颜色使用 `style.stroke`；标题与标题 runs 的字体、字号、字色统一放在 `style`，标题宽度使用 `size.width`。不保留对旧模型字段的兼容入口。
- 技巧详情、参数目录与可执行示例使用同一组字段；方法特有的孔位、裁切轨迹、材料列表等继续按各自语义命名。内部方法编译器的字段由单一 adapter 转换，不暴露成第二套模型参数；全部方法及变体验证示例可编译。技巧生成组可使用公共 place，技巧局部尺寸为毫米，不缩放真实材料。
- `graphic.add.geometry` 在模型工具 Schema 中直接给出圆形与星形结构：圆为 ellipse，星角数放 `options.points`；轨迹点 `geometry.points` 是另一个用途，不混用。
- 阶段提示和 Skill 区分整页背景与局部打底；装饰方法明确贴住纸边、跨接接缝和手机整页可见的尺度，避免只有空角微点。
- 每轮尾部提供累计秒数和距离六分钟目标的余量；鼓励合批处理，不强迫作品在有缺陷时标记完成。低思考单次响应上限 90 秒，超时重试直接执行、不重复长思考；返回 trace 记录实际档位与重试次数。服务任务的硬时限保持原值，验收单独使用六分半上限。

五类方法提示固定放在初始上下文中，不按程序记录的阶段每轮重发。模型未声明重点时，动态状态显示“由模型自行判断”，进度不冒充处于构思阶段；声明只更新展示信息，不触发阶段门槛。

## 局部更新

`layer.update` 默认只修改提供的字段，无需额外复用开关。与创建共用 `place / size / style / geometry / order / content` 名称；嵌套对象合并，数组整体替换，允许 null 的效果以 null 清除。可以只传 `place:{rotationDeg:5}`、`size:{width:40}` 或 `style:{outline:{widthMm:0.6}}`。未提供的位置、其他尺寸、描边颜色和层序保留；文字高度仍根据内容排版，实体材料仍不可缩放。

更新按当前 Scene 展开后验证，不重放旧模型调用。linked 定位沿用现有参照、坐标单位和跟随关系；没有 linked 定位时，省略参照与单位使用当前页面毫米坐标。普通图形与笔迹修改单一尺寸保持另一维，明确 `aspect:"preserve"` 才按比例调整。新建描边等效果仍需完整必要属性；部分修改只对已存在的效果成立。组合、锁定、素材来源和事务回滚约束继续执行。
