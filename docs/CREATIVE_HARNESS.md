# 服务器创作 Harness

状态：SQL、云函数与计算服务器已部署；App 已接入并在真实 CloudBase 账号验收，静态站发布另核对准确 SHA。

## 运行合同

手机提交当前方向、素材 ID、页面设置和 Scene，不传素材图片；4090 从 CloudBase 读取已同步的账号素材及私有图片，在服务器生成创作用 PNG。CloudBase 验证账号、冻结本次输入并记录任务。现有 `shiye-job` MQTT 唤醒计算服务器。模型 API 使用 DeepSeek Flash 思考模式；CPU 运行编排与 Canvas 渲染，GPU 可供图像工具使用。关闭手机不终止任务。任务状态、作品、检查点和预览以 CloudBase 为准，MQTT 只发送任务 ID 和修订通知。

LangGraph 1.7.5 承担检查点和恢复；拾页的协议 2 原子事务承担真实素材的尺寸、用量、来源和幂等约束。后台开局只加载核心 Skill 目录；定方向阶段给主题、配色与构图线索，打底构图阶段给少量匹配模板和案例参考，装饰书写阶段才自动提供可执行的标题、配色与局部点缀方法卡。其他教程按需读取，方法摘要写入检查点。首轮将全部授权素材排成一张稳定编号总图；第一张真实预览后不再每轮重复发送总图，需要时用 `workspace_view({id:"source"})` 重看，局部细节用 `inspect_materials`。默认有创作区和暂存区，可按需创建独立试摆空间；编辑后只发送发生变化的非空空间图及最新 Scene，清空的空间发送状态。旧空间图可按需用 `workspace_view` 重看。不存在生成整页位图再冒充可编辑作品的路径。

参考 [LangGraph persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence)、[DeepSeek Harness skills](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/skills)、[DeepSeek thinking/tool calls](https://api-docs.deepseek.com/guides/thinking_mode/)。采用 LangGraph 而非 DSH 的通用命令行配置，是为了复用现有原子 Scene 工具和 CloudBase 授权。DSH 当前为开发预览，默认 shell/遥测配置不直接带入业务。Skill 正文和示意图按需读取，不在开局整体预载。

## 数据边界

任务源只读；生成结果作为新的候选版本，不能覆盖任务启动后用户修改的作品。模型只能看到本次授权素材和预设。工具不提供任意 shell、网络地址、SQL 或文件路径。系统预览、最终作品和字体由现行渲染器生成。检查点可含用户文本/素材预览，放在账号私有路径；不会发往第三方监控服务。

运行截止时间从任务入队计算，恢复不重置；每轮调用使用剩余时间。重复通知仅尝试领取同一任务；租约持有者才能更新。确认取消后不再发布完成结果。通知丢失时登录、恢复前台和重连补读 CloudBase。运行中有限进度检查可以服务取消/租约，不恢复空闲数据库扫描。

## 手机与后台

编辑器与搭配页面的纯编辑入口调用 `background-creation-session.js`。它把任务输入先保存到账号隔离的 IndexedDB；任务 JSON 上传、数据库入队及 MQTT 发布成功后才显示已提交。后台使用持久 MQTT 会话，重连只核对未结束任务，不运行空闲扫描。手机离开只卸载观察器；“停止”才写入 CloudBase 取消状态。

同一来源使用原子 Scene 事务，可在一次操作中移动、裁切、排版和调整多层。创建和移动共用 `place.surface`，默认值为 `page`，暂存区为 `tray`，其他 ID 由 `workspace_create` 创建。所有空间共用毫米坐标、旋转、相对锚点和组合；非纸面对象保存在 Scene 中，由组合根节点决定其空间。`creation_undo` 可撤回最近一次成功编辑批次，随后自动重绘。工具参数按需查询；SAM 只返回提议，下一轮看过轮廓后才能真实裁切。前端收到中间图只更新预览；完成结果按原稿快照核验，人工已修改则另存候选，重复通知复用同一收据。

部署使用同一个 `shiye-compute-01` MQTT 客户端。创作有两个后台执行槽，分割保留原有槽；CPU 负责 API 调用和渲染，GPU 只在需要分割时工作。服务重启释放租约，恢复原截止时间和事务收据。

现有每日 03:00 清理任务扩展到创作中间文件，满 24 小时才回收。未接回作品保留最后预览和结果；只有云端作品记录包含完成收据才可回收最后结果。任务索引保留供恢复与诊断。纯绘画和旧混合模式入口代码仍保留，尚未迁入这个后台执行器。

## 当前边界

实体手机锁屏由页面完全卸载与重新打开模拟；未以浏览器视口代替实体 Safari 验收。失败和取消保留云端检查点与最后已发布预览，但当前 UI 尚不提供从任意中间步骤挑选并继续的版本面板。不同风格的模型输出可能仍有留白、阴影或细节需要人工调整；不以模型自审保证每次都满足审美。

## 自动反馈与轮次控制

每批改变 Scene 的事务后，后台自动渲染并提供当前 Scene、必用素材清单、最终提交校验和视觉审查任务。几何检查是程序结果，视觉判断由模型看真实图完成；两者不能混作审美通过。每次编辑后的最新图可以直接用于下一批调整；`creation_review` 可记录单次视觉判断，阶段结束则由 `creation_phase` 记录观察、问题和下一步。当前阶段的阻断问题先修；可在下一阶段处理的细节必须写明行动并带入。未解决的问题不能在同一画面版本上改口通过。满意时可直接在 `creation_finish.review` 中交付，后台绑定准确预览和 Scene。修改后同轮完成、旧图审阅和未解决问题仍会被拒绝。审查结果和所据画面版本随检查点恢复。

多个构图方向都合理，或反复修订仍卡在同一问题时，模型可调用 `explore_drafts`。后台并行运行 2–3 个只拥有 `creation_apply` 的独立子 Agent；每个从相同主 Scene 基线生成一个可编辑候选，渲染真实截图，但不保存为主作品。主 Agent 看过候选图后用 `select_draft` 说明取舍，选中的 Scene 才替换主稿并重新预览审查。候选基线过期、没有有效事务或预览与 Scene 不一致时拒绝采用。小幅修改不启动探索，剩余创作时间不足时也不再开启新分支。

参考知识先使用仓库内唯一版本的模板与技巧目录。`search_references` 按查询词、风格、主题、纸张比例和本次素材适配检索少量候选，返回来源、匹配理由和后续读取工具；`read_template` 或 `read_skill` 才加载完整结构、示意图与调用参数，`creation_recipe` 生成可编辑 Scene。结果同源重复会降权。检索不自动把素材放入页面，模型需对照真实图决定是否采用。当前没有把其他账号的作品、未经核实的网页或向量索引混入参考库。

主 Agent 使用 `direction`、`layout`、`craft`、`review` 四个阶段。结构化 `creation_plan` 检查主题依据、颜色来源、多焦点或无单一主角的视觉锚点、布局意图及文字区，成功后进入构图。构图阶段可检索模板与案例、比较草稿、摆底纸与素材簇；模板仅提供元素关系参考，不自动把示例图像放入作品。构图看过数版真实画面后提交阶段检查，把文字与装饰待办带入 `craft`。该阶段自动给少量可执行标题、配色、图形和点缀方法卡，可直接实施，也可继续查阅 Skill；不以技巧数量作为交付门槛。`review` 可继续编辑和看图，最终 `creation_finish.review` 必须绑定最新画面且没有阻断问题。布局、装饰和交付检查另调用一次只看真实截图的独立视觉审查；其明确的阻断问题必须先修改并重新预览，结果与 PNG 指纹一起写入检查点和画质时间线。独立审查不可用时记录故障，由主 Agent 的阶段检查继续执行，不能伪称双重通过。丰富风格允许多个视觉中心、叠放遮挡和充实排版，不设中心主图与固定留白比例。

每次真实渲染都会保存画面 SHA、Scene 版本、缩小像素样本、必用素材覆盖、几何提示和模型审查。相邻版本计算缩小图的平均像素变化，用来定位“修改是否真的改变了画面”，不当作审美评分。人工审阅可按画面 SHA 附加到同一版本；验收报告对比首稿与末稿，并保留每次修改。模型调用、工具执行、渲染各写一条不含图片和密钥的时间线事件，记录阶段、耗时、版本和结果。真实图片与完整检查点仍留在任务私有目录。

CloudBase 完成态任务在账号私有前缀 `reports/evaluation.json` 和 `reports/trace.json` 保存评测与时间线。本机验收脚本在私有输出目录生成同名文件；实际看图后可用 `node scripts/score-creative-harness.mjs <验收目录> <人工审阅 JSON>` 写入按画面 SHA 绑定的 1–5 分与具体说明。模型审阅、几何提示与人工评分分开记录，不能互相冒充。

启动时提供真实毫米尺寸、必用/优先级、任务约束、精简的常用合同和稳定素材总图；失效参数返回相应操作说明。少量素材时总图宽度按实际件数缩小，缩略图格子不缩小。第一张真实预览后，原始总图仍留在检查点，但从重复模型上下文移除；可按需重看。无变化的空间图不重复发送，单件细看图在模型用过后退出上下文。连续局部微调收到合批修复提示，不自动判定作品合格。模型请求由当前 Scene、按阶段保留的创作摘要、最多八轮最近工具往返及本轮新变化图组成；未变化的预览图在下一轮退出上下文，仅保留指纹和结构状态；旧历史保留在检查点，已读方法的原则、步骤与检查点单独保留。创作摘要保留已确认的构图意图、被否定方案及理由、未解决问题和下一步，使用独立的只读模型调用生成。摘要失败时不推进压缩边界。定方向与各阶段开始保留较强思考，其余编辑轮使用低思考强度。每轮记录模型耗时、截断标记和输入图片数。视觉编辑 Agent 的对照见 [研究记录](VISUAL_AGENT_RESEARCH.md)。

每次自动渲染以实际像素指纹标记纸面和试摆空间，核对预览空间集合与当前 Scene，保存各空间的对象、是否为空及最近观看轮次。下一轮只发送变化空间的图片，同时提供全部空间的结构状态；若模型要依据未重发空间的视觉细节继续摆放，可用 `workspace_view` 重看同一画面版本。编辑调用可附 `decision`，把这次调整的理由与所依据的画面版本一同写入检查点；计划、撤回和最后审阅也进入有限的决策记录。最终交付仍须绑定已观看的纸面预览，修改后旧审阅失效。长期创作取舍由滚动摘要保留，准确位置始终从当前 Scene 读取。

2026-11-20 的一份真实任务记录显示：26 轮、589069 ms，一轮纯思考耗尽 10000 token 后截断，参数纠错、连续单对象微调以及提交时才发现遗漏必用素材消耗了额外轮次。最后请求输入 122720 token。自动反馈优化据此提出；保留实物约束和最后看图检查。实测耗时需区分本机执行与 App 上传/云端接回。

2026-11-21 的四件真实素材本机测试，在引入方法卡与合批配方后完成创作：30 轮、350951 ms、输入 563177 token（其中缓存命中 313728）、输出 41212 token，产生 6 张画面版本。最终可编辑 Scene 保留四件实物、错落标题、跨页引导线和来自素材颜色的衬条；人工看图认为标题与配色已落地，右页仍偏疏，不能仅凭模型自审认定普遍画质合格。随后增加了首张预览后按需重看总图、收窄细节工具和只在首次布局阶段保持高思考的省 token 改动；新代码的真实复测在第 6 轮被 DeepSeek 返回 HTTP 402，中止于首次预览，尚无可比较的完整用量或最终画质数据。此前的 30 轮数据不能当作省 token 改动后的效果。

2026-11-22 用八件真实素材测试四阶段流程：27 轮、529442 ms，七张真实画面，八件素材均进入可编辑 Scene。方向计划于第 2 轮通过，布局、装饰、审查依次完成。人工核对末图发现左页正文压住素材原有印字、右页视觉重心失衡、边缘竖字过近；主模型的自审却宣称没有问题。同一截图的独立 DeepSeek 视觉审查指出了上述三项具体缺陷，因此增加阶段边界的独立截图审查，并移除导致两轮无效编辑的预览次数硬限制。最终画质和 App 实际运行仍需新代码复测，不能以本轮模型自审宣称通过。

同日的八件素材复验在 522775 ms 完成，布局与文字区比首轮清楚，但独立审查的思考模式两次超时，未能形成有效画质门槛。随后把只读截图审查改为 DeepSeek Flash 非思考模式，单独对旧问题图实测约 3 秒返回；它与主创作模型分开记录。快速审查的完整复验从真实八件素材启动，途中在第 22 轮因压缩边界落在同一次工具调用的两条回执之间，API 返回 HTTP 400。修复对话边界后从原检查点恢复，最终 28 轮、538694 ms 完成。布局和装饰阶段的独立审查均返回有效观察，成品为双页、六件实体素材、七层文字和四层可编辑图形；另外两件仍可留在暂存区，不强行摆满。人工看图认为主题、文字可读性、叠放与配色明显改善，装饰仍偏克制，不能把这一次成功概括为所有风格都合格。此轮是本机真实模型验收，不等于手机端到端验收。
