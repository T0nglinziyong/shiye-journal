# COS 孤立原图的服务端受保护回收

此流程仅处理当前账号路径下、文件名为 64 位 SHA-256 的 COS 原图、固定 `preview480.webp` 派生图及 `project.json[.gz]` 作品文档。素材库不可见但被创作引用的图片继续保留。浏览器没有清理接口或 COS 删除签名；容量页面的“待核对候选”不是删除依据。其他未知格式和账号重置中的文件不由本任务删除。

## 启用前提

1. 先对目标 Supabase/COS 账号完成完整备份、哈希校验与隔离恢复演练；保留备份位置和恢复记录。可使用 `scripts/cloud-backup-cli.mjs`，具体参数先运行 `--help`。不要把备份或私人素材提交到仓库。
2. 在目标 Supabase 项目执行 `supabase/migrations/20261013114054_protected_cos_orphan_gc.sql`，确认 `shiye_gc_claim`、`shiye_gc_release`、`shiye_gc_prune_trash`、`shiye_gc_prune_blob` 只对 `service_role` 可执行。不要在未备份的正式库上直接应用。
3. Vercel 目标项目需有 `CRON_SECRET`、`VITE_SHIYE_SUPABASE_URL`、`SHIYE_SUPABASE_SERVICE_ROLE_KEY` 和现有的 COS 服务端密钥、桶名、地域。先只读运行定时任务并检查日志；默认 `SHIYE_COS_ORPHAN_GC_DELETE_ENABLED` 不为 `true`，不会复制、改元数据或删除。
4. 只在备份与恢复演练、数据库迁移、测试站真实账号验证均通过后，对相应项目设置 `SHIYE_COS_ORPHAN_GC_DELETE_ENABLED=true`。正式项目还必须单独设置 `SHIYE_COS_ORPHAN_GC_PRODUCTION=true`；推送代码不会自动打开物理清理。

定时任务每天 UTC 03:30 运行（中国时间约 11:30；Hobby 套餐可能在该小时内延后触发），每轮按账号 ID 顺序轮转处理一个账号，最多读取 1 万条关系记录和 2 万个 COS 对象、执行五项动作。超过上限或分页、引用、版本核验不完整时直接停止该账号，不会基于部分清单删除。账号数量较多时应评估轮转覆盖时间和 Vercel 执行时长；账号数增加后，单账号轮转间隔也会相应增长。

## 状态与恢复

| 阶段 | 门槛 | 动作 |
| --- | --- | --- |
| 最近删除到期 | 删除记录超过 30 天、修订号未变 | 服务端移除最近删除卡片；若同轮存在到期卡片，本轮不再扫描或删除 COS |
| 只读候选 | 受管对象超过 90 天、完整引用扫描显示无在用记录 | 记录数量；默认到此为止 |
| 私有隔离 | 开启清理开关，版本未变 | COS 服务端复制到账号下 `gc-quarantine/`，校验大小和 ETag；原图保留 |
| 元数据回收 | 原图的隔离副本超过 30 天 | 在修订行锁内复核其他云端记录，通过后删除孤立 `blobs` 行并写入增量变更；没有 `blobs` 行的派生图/文档跳过此步 |
| 活跃对象回收 | 隔离副本超过 60 天 | 再次核对版本、引用、活跃对象与隔离副本；删除活跃对象，保留隔离副本 |
| 隔离副本到期 | 隔离副本超过 180 天，原图仍不存在且无引用 | 删除隔离副本 |

若新引用出现而活跃对象已删，下一轮会从私有隔离副本恢复。删除时若修订变化，本轮立即恢复并报错。遇到冲突、租约占用、COS 复制校验失败或对象变化时不继续删除。日志不输出用户 ID、文件路径、令牌或私有内容。

最近删除的逻辑保留期是 30 天；启用清理开关后，到期记录会按账号轮转自动移除。被作品引用的隐藏素材仍保留；即使无引用，隐藏素材的元数据也不会由此次服务端任务贸然删除，因为作品文件、历史和其他设备待同步引用尚不能靠单次关系表扫描完全证明不存在。它需要客户端完成现有引用检查，或后续增加服务端完整作品文件引用索引，才能进入原图回收。其他 COS 物理字节也因完整引用复核、90 天对象年龄门槛和隔离备份，晚于 30 天释放。不可把“最近删除已清空”理解为“私有备份也立即清空”。

此保护针对**已同步的云端引用**；关闭中的其他设备仍可能持有尚未上传的草稿或待同步队列。90/30/60/180 天等待期降低风险，但不能数学上证明设备永不重新上线。外部备份也不作为在线引用，务必独立保留完整备份。若要求在任意多年离线设备重新上线后仍能恢复，不能在 180 天清空隔离副本，应保持物理删除开关关闭，或进一步建立服务端可验证的设备水位线/永久备份策略。

回滚时先将 `SHIYE_COS_ORPHAN_GC_DELETE_ENABLED` 改为 `false`；已隔离但尚未删除的原图不受影响。隔离副本仍在时可按账号与 SHA 路径从 `gc-quarantine/` 复制回原路径，并复核 Supabase 引用与增量同步。隔离副本已过期时只能依赖启用前保留的完整外部备份。不要通过浏览器的容量页做恢复或物理删除。
