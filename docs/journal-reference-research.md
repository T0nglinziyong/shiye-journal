# 手帐案例研究与素材取用边界

本轮逐张观察用户提供的 70 张截图。必须先区分**抽象模板图**、**真实手帐成品图**、**同一截图内两者并列**及**非创作资料**；风格相像不足以证明某模板与某成品一一对应。逐张类别保存在 `src/journal-source-audit.js`，从多画面截图拆出的 70 条独立版式关系保存在 `src/journal-abstract-templates.js`，实际裁切位置见 `src/journal-source-panels.js`。第 32 张只有成品示例，不当作抽象图；第 47 张是手帐尺寸和孔距对照，仅作尺寸参考，不当作模板或成品。截图只用于来源核对；仓库与线上公共静态目录不放截图、原文、水印、人物照片或从第三方作品直接裁出的贴纸。

本研究保留案例家族、抽象模板与来源图之间的核对记录，供设计指导维护使用。当前 AI 创作和网页任务包均不再自动发送这些案例、模板说明或参考图；模型只接收本次选中的素材。历史图像与文字资料不是可用实体素材，也不应混入本次创作输入。

由此形成六种可混合的构图家族：图文日记、路线与时间轴、食物观察、纸片错层、杂志式记录、清单与问答。素材按版面职责分成书写底纸、主视觉、生活凭证、书写卡、连接材料、小装饰；原有 `kind` 仍表示存储类型，不能代替版面职责。默认创作参考使用这些抽象规则，匹配推荐会考虑尚缺的职责，但不设置素材件数或填充率的审美硬指标。

公开资料核对：

- [Hobonichi 用户装饰方法](https://www.1101.com/store/techo/en/magazine/tt_report/202304/) 展示彩色索引、纸胶带与小图案如何配合书写。
- [Hobonichi Weeks 用法](https://www.1101.com/store/techo/en/magazine/contents/weeks/index.html) 展示日志、餐饮记录、照片和贴纸并用，而不是单张大图覆盖页面。
- [Bullet Journal 日志方法](https://bulletjournal.com/blogs/faq/how-to-write-a-daily-log) 明确任务、事件和备注的记录结构。
- [Bullet Journal 用户案例](https://bulletjournal.com/blogs/bulletjournalist/show-tell-with-yu) 展示个性化的书写与图像组合。

## 提取与替换原则

“从案例中抠取”指从有权使用且能确认完整边缘的原始素材照片提取真实物件，不是把整张手帐页或教程截图裁成一个贴纸。提取件要逐一检查：无作者水印、无他人私密文字或肖像、主体没有被遮挡、边缘和透明度可用、像素足够印刷、实体尺寸可校准，并记录来源与使用许可。用户账号里的私人素材可以另走私有存储；公共内置素材必须先确认可公开再随代码发布。旧内置素材可能被现有作品引用，替换时先保留旧资源可读，不删除用户作品或改变既有素材 ID。
