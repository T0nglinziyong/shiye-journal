# 小小彩虹三页渐进研究：标题、正文与装饰

接续 `rainbow-dual-difficulty-2026-11-23.md` 的五篇双难度打底研究。先选择 A 难度 D143、D153、D158 的较稳定打底，B 难度的纹样、孔洞和纸边问题仍需修正。只学习原作的风格、内容和关系，不要求像素复刻；画面丰富度与文字量是不同参数。

## 可追溯的接续方式

每轮保留原教程参考，重新向真实 DeepSeek 提供原作及本轮起点的实际渲染图。从上一轮 v3 可编辑 Scene 继续，先验证源任务指纹、用户方向、纸张与材料账本，再明确导出为当前合同的新研究任务；没有直接替换 schemaHash，也没有修改原项目。seed.json 记录起点项目 SHA256、预览摘要和 Scene 版本。

阶段依次为标题、正文、装饰。每阶段首张有变化的预览后停止，不继续收费生成总结、独立评价或完整作品。所有结果仍标记 completedWork=false、visualQualityPassed=false；技术成功与人工视觉评价分开。真实输出和原失败版本保留在私有归档 `双难度教程研究-2026-11-23/progressive/`，不提交私人素材。

## 标题首轮发现

- D143：橙色下划线压住极细副题。
- D153：白鹿棒棒字体的“喜欢蓝色”意外将“色”换到下一行，落到灰绿纸上。
- D158：大标题的窄框把词组变成竖列，白字进入浅色便签，与 Q1 小标题和未来正文互撞。

原因并非只缺少提示词：`text.add` 的 height 是最小高度，文字会继续换行扩展；`text.fit` 原先按估算字宽计算，而出图按实际字体计算，二者结果不同。正文同样会受影响。

## 工具与 Skill 修正

- Harness 渲染器提供与出图同字体、字号和字距的 Canvas 测量回调，经主 Harness 与 Pi 桥传入事务执行；`text.fit` 使用真实字体测量，未接渲染器的纯数据调用仍为明确的估算，不宣称像素一致。
- `text.fit.fit.maxLines` 支持限制行数，单行题签可设为 1；保留全部内容，最小字号也放不下时原子回滚，不截字。实际字体回归覆盖“喜欢蓝色”单行适配与失败回滚。
- 标题 Skill 明确字体差异、最小高度与可用框的区别、单行或有意分行、反白字跨浅底、下划线与副题的空间关系。
- 正文 Skill 明确使用连续可读写面、真实字体适配、末行越界的修改方法，不能无限缩字或另铺统一大卡片。
- 渐进提示明确先记录局部方案再修改，用户方向保持不变；首版要求改色使用 layer.update；真实修复中模型反复在 text.fit 传入 style，说明拆分不自然。随后扩展 text.fit 同时接受字体、颜色、行距等 style，先按新样式测量再适配，最终字号由 fit 决定；新增换字体后的单行适配与颜色保留回归。
- 修复研究初始 3 次 HTTP 上限在帮助查询和纠错后过早耗尽的问题：后续非打底阶段允许 5 次 HTTP、300 秒，仍在首张新预览后停止。思考模式和输出预算保持高思考、普通请求 14000 tokens、适配器低思考重试 8000 tokens。

## 边界

这些是使用参考图、阶段起点图和人工问题描述的受指导修复实验，不能据此宣称模型无人指导即可稳定完成。素材含对遮挡部分的推定恢复，不能把它们称为作者完整原始商品扫描。阶段完成后仍需跨案例与 B 难度继续检验。

## 正文首轮发现与改进

D143 首轮修好了细副题，但 Q2/Q3 白字末尾越出深色纸，对比不足。D153 中段白字跨过浅色便签与蓝胶带，底部清单末行超出横线纸。模型均仅设置了文字最小高度，没有使用真实适配。研究提示补充逐段按连续可读区域适配、内缩真实纸边、不同深浅写面不得共用反白段落；随后进行定向真实修复，保留首轮失败图。

D158 正文首轮 3 次 HTTP 均未返回有效结果，报告 CREATIVE_MODEL_TIMEOUT；无返回 usage 不等于没有计费。旧模型适配器对高思考单次仅等 75 秒、低思考重试 45 秒，复杂文字轮可能连续丢弃尚未完成的请求。现分别放宽为 150 秒和 75 秒，始终受任务剩余时间限制，快速判断和摘要超时不变。回归测试验证较长深思等待仍被任务截止时间限制。

## 装饰首轮发现

D143 虽解决了副题对比，但新增的页边点列近似重复装订孔，橙蓝页边标签生硬。不是用更少装饰作为通用标准，而是要求新增细节与具体文字、图像或接触点有关。装饰 Skill 补充装饰前后比较、区分材料纸边与整页裁切边、避免复制已有孔洞列，允许撤掉无关点列后换成相关线稿或关键词强调。随后从真实首版继续定向修复，保留初版对照。

D153 装饰调用还出现 layout.nudge 使用 target 而非 targets、graphic.add 使用 lineWidth 而非 strokeWidthMm。错误反馈能给出当前参数并原子回滚；没有把任意别名静默接收。它们仍说明工具合同学习成本需要继续关注，单凭本轮成功出图不能称为调用稳定。

D153 的装饰首版暴露文字回归：把举牌短句从图注尺度提高到 20pt，只改最小高度而没有适配，出现三行大字压住人物；竖排短注也重新断行。再次修复使用明确的可用范围和 maxLines，并提示不要在装饰阶段把图注升级为主标题。此轮有人给出具体毫米范围与字号建议，是受指导能力验证，不是无人指导成功率。

D143 装饰修复撤掉了重复页边点列，新增与“绿萝换水”内容相关的小枝叶和批注；正文可读。标签形态、短注断句等局部仍有改进空间，保留未全面通过的标记。

## 本轮结果与验证

最终选择三例均为 accents-v2：D143、D153、D158；标题、正文和装饰每一阶段及失败版本都可在私有 progressive/index.html 对照。D153 的举牌短句、便签和竖排边注已恢复可读；D158 的格纹胶带移入下方卡片组，贴正文的橙点与灰箭头已撤掉。仍有局部标签生硬、短注断句、正文尺度与装饰套路化问题，没有全面审美通过，也没有宣称无人指导稳定。B 难度尚未进入这些阶段。

本轮 19 次真实阶段运行、55 次 HTTP、17 张模型阶段预览。返回 usage 合计 1,590,020 tokens（含输入、输出与思考；50 条 usage）。另有 5 次 HTTP 未返回 usage，不能按免费计。3 次最初的旧合同接续预检失败发生在付费调用之前，未算入这 19 次真实运行。打底研究的既有 27 次运行另计，两部分合计 46 次运行、118 次 HTTP、2,849,411 返回 tokens。没有估算人民币费用，实际账单以服务商为准。付费调用已停止。

验证：`npm test` 共 2053 项，2052 通过、1 跳过、0 失败；`npm run test:ui` 7 种视口通过。三个最终可编辑项目通过当前格式导入与材料账本核验；实际字体尺寸审计 25 个文字节点，没有超出自身文字框。文字框审计不检测不同纸面的对比、遮挡或审美，人工看图结论单独记录在 visual-review.json。输入参考、阶段预览和起点项目 SHA256 核验通过。
