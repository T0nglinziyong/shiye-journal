# 拾页创作页面稳定性与创作能力改造指导

本文件交给后续实施 AI 与开发者使用。首要任务是修复用户在创作页面进行各种操作时遇到的错误，保证画面、作品数据、撤销重做和保存重开一致。随后扩展手工创作、网页版 AI 创作以及交互数字手帐。不要先增加大量新工具，再试图补救不稳定的编辑基础。

审查日期：2026 年 10 月 16 日。审查基线为 test 分支，HEAD b06d85c32b61a28d33f59b605a82977878e94a0b 及审查时工作区；工作区存在 103 项未提交变动，因此 HEAD 不能完整代表所审代码。实施前重新核对相关函数，不覆盖其他正在进行的修改。本次只编写修改指导，没有修复业务代码。

本文与《同步与创作数据改造实施说明》《基础建设与页面性能改造实施说明》配套。涉及同步、缓存和库存规则时沿用用户已明确的要求；本文重点是编辑行为，不另行决定云端自动上传频率。无法承诺任何方案永远没有 bug，交付应以明确的行为规则、可复现回归和故障恢复能力为标准。

## 1 修改顺序与不可退让的要求

第一阶段处理会丢失修改、误改锁定内容、撤销失效、保存重开变样的问题。第二阶段统一选择、组合、文字、笔迹和裁切的操作规则。第三阶段增加可视化创作工具与 AI 创作包。第四阶段加入翻片、口袋和页面跳转等交互。

- 一次完成的用户操作对应一个可撤销事务。预览、取消、无实际变化的确认不产生事务，不清空重做，不触发作品内容上传。
- 用户看到“已保存到本机”时，修改必须已可靠落盘；“已同步”必须有服务端确认。图片封面、字体加载和缩放变化不算作品内容修改。
- 锁定限制必须由公共修改入口执行，涵盖工具栏、快捷键、图层面板、画布、多选、组合、AI 与导入，不能只禁用 Fabric 控制柄。
- 同一份持久作品数据驱动手工画布、AI 预览、缩略图、导出与重开。Fabric 对象是投影，不成为第二套作品真相。
- 用户不手动解决字段或 JSON 冲突。作品发生真实并发保存冲突时自动保留两份；其他实体按既定最新写入规则处理。不要因查看作品或加载资源制造冲突副本。
- 去掉库存扣减。使用状态只影响推荐，不限制正常选取和跨作品复用。单个作品内同一普通素材按一个来源对象管理；裁切分片应归属于它，不能靠换 ID 绕过限制。胶带分段与是否自动标记已使用按专门规则实现，默认不自动改变胶带使用状态。

## 3 优先修复的实际操作问题

### B01 多选拖动没有可靠写回作品

级别 P0，证据 A 与 B。用户框选两个对象后拖动或旋转，可能出现拖动画布、选择丢失，或者看似移动但重开恢复原位。

依据：src/fabric-scene-stage.jsx 的 before:transform 和 object:modified 依赖 target.sceneID；Fabric ActiveSelection 没有此字段，提交直接返回。夹具中将素材与文字构成 ActiveSelection 并平移 50，变换事件后素材 Scene x 仍为 340。src/react-routes.jsx 的 canTransform 又仅根据 state.selected 判断，未覆盖多选状态。

修改要求：多选统一使用完整选中 ID 集合；事务开始记录所有实际对象的世界变换，结束时将 ActiveSelection 的变换分解回各对象的持久坐标。组选择不得与普通多选混淆，不能既修改组又二次修改其子节点。修改成功后统一提交；任一目标无效时整体回滚。手势层须识别多选控制框与其成员，不能误转为平移页面。

验收：两对象及跨组合的合法选择分别移动、旋转；松手、撤销、重做、保存重开均保持相同位置。实物素材不允许通过多选缩放绕过真实尺寸规则。用真实指针事件覆盖完整页面，不能只 fire Fabric 事件。

### B02 多选更新可能只保留新加入的对象

级别 P1，证据 B。selection:updated 回调使用 event.selected 生成全部选中 ID；此事件载荷用于表达选择变化，不能假定等于当前完整集合。

修改要求：统一从 canvas.getActiveObjects() 或受控选择模型读取最终集合，再按作品树去重和规范化；异步创建 ActiveSelection 使用选择代次，旧任务不得覆盖新选择。

验收：选 A，再加入 B，再加入 C，最后移除 B；画布、图层列表、工具栏、删除目标始终分别为 A、AB、ABC、AC。连续快速切换和撤销后不能幽灵选中。

### B03 组合选择与子元素选择无法贯通

级别 P1，证据 B。src/app.js 的 editorEntry 取 sceneLayerEntries 且排除笔迹，该遍历只返回叶子，不含组。fabric-ungroup-selection 却试图从同一结果寻找 group。因此选中组合根后解除组合可能无响应。Fabric 外部选择映射又只查 canvas.getObjects() 根对象，图层面板选中嵌套元素不一定能在画布得到同样选择。

修改要求：建立返回所有可编辑节点的公共查询，区分根组、组内元素、笔迹与装饰投影。组内编辑用双击进入或显式“进入组合”，提供面包屑和退出动作。删除、复制、解组、对齐等命令按节点类型分发；不得把非 shape 类型全部当成 text。

验收：建立组合后立即解组；从图层面板选择组内文字，移动、改色、删除；选择笔迹组后删除并撤销。不存在“选中了但工具没有作用”的状态。不能编辑的投影须说明原因。

### B04 锁定规则被组合变换和属性工具绕过

级别 P0，证据 A 与 B。桥接 applyObject 的组合变换会递归更新锁定子元素。函数复现中 locked 子元素 x 从 20 变成 70。app 的 fabric-text-property、fabric-shape-property 等分支直接改属性，未在写入处统一检查锁定祖先。

修改要求：统一 effectiveLocked(node)，包括自身与祖先。建议组合含锁定子元素时禁止整体变换并解释“组合内有锁定内容”；如未来提供“锁定相对组内位置”必须另设模式，不能暗改现有锁定语义。所有命令先验证，再开启事务。只允许解锁命令修改锁定状态。

验收：锁定素材、文字、形状、笔迹及包含它们的组，分别尝试拖动、裁切、删除、改色、翻转、排序、多选、AI 修改。被拒绝的行为不能改变数据或清空重做。

### B05 橡皮可能擦掉隐藏或锁定笔迹

级别 P0，证据 B。FabricSceneStage 的 inspectTree 递归擦除全部 ink，没有检查自身或祖先的锁定与可见状态。用户擦当前可见线条时，可能同时破坏重叠位置的隐藏内容。

修改要求：命中集合先经过有效可见、有效锁定、当前编辑容器和擦除范围过滤，再计算笔迹分片。擦笔迹与擦素材透明区是不同工具，不能静默混用。擦除分片保持笔压、颜色、来源和顺序，一整次擦拭为一个事务。

验收：相同位置叠放可见笔迹、锁定笔迹、隐藏笔迹以及隐藏组内笔迹；只改变允许擦除的对象。部分擦除、整笔擦除、撤销和重开结果一致。

### B06 新笔迹进入隐藏或锁定的自动笔迹组

级别 P1，证据 A。src/ink-groups.js 的 appendInkStroke 只按最上层 autoInkGroup 及子节点类型追加。复现中 locked 且 visible=false 的组新增了一个子笔迹。用户可能写了却看不见，也可能破坏已锁定组。

修改要求：只有当前可见、可写且属于当前创作上下文的自动组可追加；否则创建新的可见笔迹容器。新容器不应因为旧组 zIndex、隐藏状态或上一次工具选择被错误归属。

验收：隐藏或锁定最后一个笔迹组，继续书写；新笔迹可见、能独立撤销，原组内容完全不变。打开口袋或翻片后书写也须明确归属哪个内容面。

### B07 无变化操作吞掉撤销并破坏重做

级别 P1，证据 A。src/editor-history-scope.js 的 checkpointEditorHistory 立即清空 redo；takeEditorHistoryStep 遇到空差量时弹出并返回 null，没有继续找到上一个有效事务。最小复现：移动对象，再建立未修改 checkpoint，第一次撤销无效，第二次才回退；撤销后一次空 checkpoint 使 redo 从 1 变为 0。

修改要求：使用 begin、preview、commit、cancel 明确事务；只有 commit 有语义差量时才清空 redo。历史读取自动跳过历史遗留空项；输入无效或取消不会进入历史。滑条一段手势、拖动一次、裁切确认一次、整笔书写分别是一个事务。相邻文字输入可按编辑会话合并，但不要跨对象或跨作品合并。

验收：移动后点开属性再取消，一次撤销就回到移动前；撤销后点击、缩放视图、无效输入、拖动回原位均保留重做；连续撤销至底再重做至顶，最终规范化数据相等。

### B08 文字拉伸后保存的字号与画面不一致

级别 P1，证据 A，最终像素差异需浏览器回归。桥接把 Fabric text 缩放写入 width、height，没有同步缩放字号。复现：fontSize=40、180×95 的文本框放大两倍，持久化成为 360×190，但 fontSize 仍为 40。需要明确这是文字整体缩放还是文字框重排，不能混在同一控制柄行为中。

修改要求：左右柄调整框宽并重排文字；角柄若表示整体放大，须同步字号、行距等排版度量并消除残余 Fabric scale。默认保持文字比例，避免扁字。字体加载、原生编辑时的测量与 Scene 导出测量统一，保留字体缺失提示和可替换选项。

验收：中英文混排、换行、粗斜体、不同字体、旋转文字分别缩放；退出文字编辑、保存重开、缩略图与导出文字大小一致。中文拼音组合输入不丢字，不在 composition 中途提交、重绘或触发快捷键。

### B09 手工缩放和 AI 实物尺寸规则不一致

级别 P1，证据 B，已有桥接测试明确允许素材改变宽高。src/fabric-scene-bridge.js 未禁止普通 material 缩放，AI 路径则有真实物理尺寸验证。用户手动得到的作品可能无法由 AI 接续或导入校验。

修改要求：明确素材能力，而不是全部禁止缩放。实物素材保持真实尺寸，通过裁切改变可见区域；数字贴纸、文字、形状允许按规则缩放。实物模式显示直观“裁剪”“选取胶带段”，不要展示会造成错误拉伸的柄。数字模式若允许非等比拉伸须明确选择。AI 与手工都经过相同能力验证。

验收：手工产生的全部合法作品能被 AI 读取、无修改打包与重新导入；AI 产生的对象在手工界面具有相同可编辑能力。不得自动缩小实物素材来掩盖越界。

### B10 解除组合改变外观及叠放关系

级别 P1，证据 A 与 B。scene-v2.js 的 ungroupSceneLayers 直接替换为 children；组 opacity、blendMode、vectorMask 未保留，子层 zIndex 也未统一重排。复现组透明度 0.4，解组后子对象 opacity 仍为 1。混合和遮罩不能总靠简单乘透明度保持等价。

修改要求：把“解组后外观不变”作为契约。简单组可正确展开变换并重新排序；有复杂组效果时保留非破坏性效果容器，或者禁用会改变结果的解组并说明原因。不得静默栅格化使内容失去编辑能力。组合含组合的重编组也须支持或明确限制，当前 groupSceneLayers 的叶子查询不能处理组 ID。

验收：半透明重叠对象、正片叠底组、带镂空组、嵌套组分别解组，和解组前做渲染对比；撤销恢复完整树结构与层级。

## 4 需要在真实页面补查的高风险场景

本节为 C 类检查项，不宣称已经复现。实施者应逐项给出通过记录或新缺陷编号，不能以“未看到报错”结束。

| 场景 | 可能暴露的问题 | 必须验证的结果 |
| --- | --- | --- |
| 拖动中松手到画布外 | 未收到结束事件、悬挂事务 | pointer capture 与结束/取消策略明确，后续操作正常 |
| 单指拖动中加第二指 | 误移动对象、缩放跳变 | 平移缩放和编辑手势互斥，取消不污染历史 |
| 写字中切工具、返回、后台 | 最后一笔丢失或重复 | 已完成笔画落盘；未完成笔画按统一策略提交或取消 |
| 文字输入时切作品 | 字写入另一作品、输入焦点残留 | 编辑事务绑定账号、作品、页面、会话代次 |
| 快速选不同对象 | 属性面板仍显示上一个值 | 检查 defaultValue 与组件复用，草稿输入按对象隔离 |
| 缩放和平移后裁切 | 屏幕坐标被当成纸张坐标 | 旋转、页面缩放、DPR 下命中与预览一致 |
| 修改纸张尺寸或横竖方向 | 内容位置、物理比例变化 | 所有入口复用纸张变换逻辑，预览、确认、撤销一致 |
| 图片首载失败后重试 | 签名缓存阻止重投影 | 失败状态不等于已投影；重试成功原位恢复 |
| 高清或字体延迟到达 | 抢选择、旧对象覆盖新编辑 | 资源替换校验会话、节点修订和请求代次 |
| 删除对象后资源请求完成 | 被删除对象重新出现 | 过期结果丢弃，不能重建节点 |
| 切作品后旧异步任务完成 | 旧图片、AI 结果进入新作品 | 所有异步提交校验原目标与基线 |
| 字体切换后直接导出 | 预览与输出字体不同 | 等待必需字体或明确降级，不假装预览已验证 |
| 已保存状态下修改封面 | 再次上传或产生 AI 候选冲突 | 内容语义摘要排除派生字段；核查 AI 全量 JSON 比较 |
| 连续打开关闭大作品 | 内存增长、卡顿、重复监听 | Canvas、预览缓存、对象 URL、监听和历史有生命周期 |
| 保存时空间不足或断网 | 界面声称成功却无法恢复 | 本地失败保留内存及恢复出口；云端失败不阻塞编辑 |

还应检查 FabricSceneStage 的 object:modified 异常分支：目前捕获后报告错误，需保证已部分写入的数据和视觉变换同步回滚；错误提示不是事务恢复。场景刷新不得依赖可能同毫秒相同的更新时间字符串，应使用可靠的本地修订计数。已有 AI 目标捕获与提交保护应复用并补充测试，不要另建一套目标状态。

## 5 统一编辑执行方式

保留 Scene 为唯一持久模型，抽取现有修改逻辑形成公共命令入口。它应接受目标、预期本地修订、操作参数与来源；返回规范化变更、受影响节点、诊断和历史事务。手工交互、快捷键、AI 编译器、导入后修正都调用同一规则层。不要把全部逻辑继续堆入 app.js，也不要为 AI 新建平行作品模型。

顺序应为：解析目标 → 验证可见性/锁定/权限/素材规则 → 在候选副本或可回滚事务中计算 → 验证结果 → 原子提交 → 局部更新画布 → 本地可靠保存 → 按既定策略进入云端队列。被拒绝的操作不改变原数据、历史或使用状态。

明确三个坐标空间：屏幕、页面、对象局部。现有 Scene v2 组子节点使用页面坐标，不能直接改成局部坐标解读。新增翻片或容器可采用局部坐标，但需有显式转换边界、完整保存合同和转换测试。旋转、裁切、镜像、组变换的顺序必须固定，并保证同一对象不会重复应用变换。

选择状态包含当前编辑容器、选中集合和主对象；悬停、控制柄、画布视口单独保存为视图状态。每次树结构变化后规范化选择：删除目标后清理，分割后选择新片段，解组后选择展开内容，撤销后不留下失效 ID。

## 6 用户友好的操作规则

用户日常只需拖动、点选、拉柄、画路径和选择预览，不要求理解坐标、比例数组、蒙版顶点或随机种子。高级面板仍可提供精确尺寸和角度，不强迫用户使用。

| 操作 | 默认交互 | 需要防止的错误 |
| --- | --- | --- |
| 移动与旋转 | 直接拖动、旋转柄、吸附参考线 | 误拖页面、旋转中心跳变 |
| 多选 | 框选/套索、点选增减、明确计数 | 只选新增项、误操作锁定层 |
| 对齐与均分 | 图示按钮、预览参考线 | 将纸张对齐误当对象对齐 |
| 层级与组合 | 可视树、拖动排序、进入组合 | 看得见选不中、解组变样 |
| 透明与混合 | 滑条、预设效果缩略图 | 一次滑动产生几十步撤销 |
| 文字 | 画布输入、浮动样式条、文本框柄 | 中文输入被重绘打断 |
| 裁剪 | 框与遮暗区域、保留部分高亮 | 预览与实际裁剪方向相反 |
| 切割 | 拖切线端点或画路径、片段预览 | 素材来源重复、碎片失踪 |
| 镂空 | 在素材内画孔、孔形可调整 | 手动编辑 polygon JSON |
| 撕边与花边 | 样式缩略图、程度滑条 | 每次重开随机变化 |
| 胶带 | 卷带预览、拖选一段、端口样式 | 拉宽真实胶带、无依据补图 |
| 笔迹 | 笔粗样例、颜色、擦除范围预览 | 隐藏层被擦、手掌误画 |
| 保存与返回 | 自动本地暂存、明确保存状态 | 等网络才能退出、重开丢改动 |

移动端工具栏不得遮住当前选中区域和文字光标；面板开关保留画布位置。长按与单击、双击进入组合需统一延迟与取消机制；辅助按钮提供可访问名称和足够点击范围。键盘删除、撤销、空格平移仅在画布上下文生效，输入框里保持正常编辑语义。

## 8 AI 与手工共用能力但采用不同输入方式

最终均落到同一个当前作品格式与同一个验证器。AI 的高层命令是创作输入协议，不是第二种持久格式；手工的手势也是输入协议。允许 AI 访问低层几何能力，保证自由创作，但不要求它逐个填写机械字段。

AI 更适合表达内容结构、层级、主题、分区、对齐、相对位置、保留主体、剪出窗口、翻片正反面等意图。编译器负责稳定 ID、单位换算、尺寸推导、变换矩阵、素材来源与约束。单纯给 AI 一个很大的 JSON Schema 会把大量精力耗在格式正确上；单纯给固定模板又限制创作。

建议提供三个层次：语义布局和样式操作；带明确对象引用的精确操作；经过相同校验的底层 Scene 编辑。命令应支持查询对象完整信息和局部修改，不能只有摘要没有点位、锁定、字体或来源信息。别名用于模型阅读，最终打包时解析成稳定引用。

AI 工具返回结构化问题：目标、约束、失败原因、可修复建议。无效的一步不能污染当前作品。完成结果先预览为候选，明确目标作品和基线；用户采纳时再次校验，没有改变的候选不产生保存。用户已手工修改的内容不能被旧 AI 任务覆盖，应按原讨论保留可比较候选。不要删除现有目标保护后另起一套机制。

取消不合理的固定艺术配额，以文档大小、总节点数、复杂路径、图片资源和耗时预算控制成本。较复杂的作品可分阶段生成并局部修复，不能因单次工具限制必须重写整幅作品。

## 9 面向网页版 AI 的创作包

创作包应开箱可理解，包含任务说明、素材信息和能验证最终结果的辅助工具。不能假设所有网页版 AI 都能运行 Node、安装依赖或启动浏览器。导出前显示包体大小、包含资料和隐私范围，不带登录令牌、私有签名下载链接或无关作品。

| 内容 | 要求 |
| --- | --- |
| START_HERE | 简短流程、环境自检、最终交付文件说明 |
| 创作简报 | 区分必须满足的内容与可自由发挥的审美建议 |
| 能力清单 | 当前支持操作、素材类型规则、单位、容量限制 |
| 当前作品与基线 | 接续创作需要完整 Scene、目标 ID 与内容摘要 |
| 素材目录 | 可读别名、真实尺寸、裁切能力、来源及使用规则 |
| 素材预览 | 带编号联系表、透明背景中等清晰图、按需细节图 |
| 字体与参考 | 许可允许的字体或可验证字体信息；参考图单独标记 |
| 示例 | 极简页面、复杂组合、裁切、交互组件的有效小例子 |
| 工具 | inspect、compile、validate、preview、pack 与 self-test |
| 输出合同 | 完整作品 JSON、依赖清单、验证报告及对应预览 |

完整环境运行与 App 一致的编译和渲染实现；只有 Python 的环境可提供轻量封装或明确标注近似预览，不能再造一套不同排版引擎；不能执行代码的环境返回简化创作描述，交由 App 编译、验证、预览后确认。环境探测失败要说明实际可用能力。

最终 JSON 是可导入的作品快照，不是必须回放整段聊天或操作日志才能恢复的结果。预览图必须由最终打包内容实际渲染，并绑定其内容摘要；没有执行就不能声明“已检查渲染”。既有素材通过稳定引用解析；新增大图或音频使用带清单的资源包，不依赖临时网址，控制内嵌资源大小。App 不执行 AI 提供的任意 JavaScript。

导入流程为文件解析、容量与结构校验、素材解析、语义验证、离屏预览、候选展示、原子采纳。缺失素材可保留占位和修复入口，但不能静默删层后称为成功。未知能力不能静默降级为静态图并覆盖可编辑原作。

## 10 可交互数字手帐

优先实现二维或轻量 2.5D 的翻片、口袋、信封、页面链接和勾选控件。复杂三维纸张物理模拟投入大，先不作为基础架构前提。

结构内容、持久填写状态和临时观看状态必须分开。结构内容包括正反面、铰链、容器、链接目标及作者默认呈现；持久填写状态包括勾选或已录入文字；观看状态包括临时打开角度、悬停、拖动抽出过程和播放进度。临时观看动作默认不改变作品、不生成撤销、不产生同步冲突。用户希望保存“默认展开”时通过明确编辑操作修改作者默认值。

| 组件 | 数据与交互要求 | 常见错误防线 |
| --- | --- | --- |
| 翻片 | 独立正反面、铰链边、开合范围 | 背面不是正面镜像；关闭时不可点到背面 |
| 口袋 | 容器开口、遮挡区域、内容所有权 | 放入后只有一个父容器；不重复复制对象 |
| 信封 | 封口和内容分离，可逐层打开 | 展开顺序、点击优先级与遮挡一致 |
| 页面链接 | 稳定页面 ID、链接标签、返回能力 | 页面改名不失效；删除目标有提示 |
| 勾选填写 | 有类型字段与持久状态，权限明确 | 只读查看者不能写入；填写也支持撤销 |
| 音频附件 | 受控引用和显式播放 | 不自动播放；离线缺失有占位 |

编辑模式负责摆放和修改组件；阅读模式负责点开、翻阅和链接；可填写模式只允许指定字段更新。手势必须区分“移动整张翻片”“打开翻片”和“编辑翻片内部”，提供明显模式和上下文反馈。

一个对象同一时刻只有一个真实父容器，树无循环。封面、预加载、备份、导出和垃圾回收都应遍历隐藏内容、背面和容器内部，不能只遍历当前可见投影。运行时投影 ID 与真实节点 ID 分开，点击映射回真实节点。动画不能直接反写创作几何；减弱动画时仍能完成全部操作。

先设计类型合同与能力版本，再实现组件。版本标识用于区分数据能力，不等于软件营销版本。遵循仓库要求：日常仅运行当前格式，旧格式通过用户主动触发的独立转换工具处理；转换先备份，不确定的记录保留原样。遇到不支持能力明确阻止覆盖或提供只读提示，不能偷偷抹掉字段。

导出静态图片或普通 PDF 时明确交互会丢失，允许选择默认面、展开视图或附加背面页。可交互导出需专用查看器或受控网页包，不能承诺普通图片保留交互。

## 11 流畅性与保存一致性

一次拖动期间只更新受影响的 Fabric 对象或临时预览，结束时提交一次 Scene 事务。属性面板和状态标签局部刷新，不因滑条或每个 pointermove 重建整个页面。切页保留视口、选中上下文和已验证图片缓存，但关闭的编辑会话不得继续接收旧任务写入。

缓存以素材内容版本、节点修订和渲染参数为键；高清替换复用对象位置与选择，复杂蒙版可缓存但要有内存上限。对离屏页面暂停动画和昂贵投影；长作品按页加载，在页面之间预取有限资源。性能验证分别测交互延迟、长任务、内存、首次打开和二次打开，不只看 build 大小。

本地仍需要增量或差量格式来支持撤销、恢复及高效保存；这不代表需要将每一步编辑同步到云端。向云端提交作品快照与本机使用差量是两个独立选择。返回或保存触发上传时，先持久化最新本地事务再构建快照；重复提交使用内容摘要与幂等键，网络失败重试同一次提交不生成新的作品版本。

打开已有作品可以先展示已验证缓存，后台检查云端；真正允许继续编辑前如何处理远端新版本应沿用同步文档的进入策略。不能用全屏长期等待来保证“最新”，也不能在用户已经输入后静默替换整个作品。

## 12 必须执行的用户操作回归

以下每组测试都要检查：即时画面、持久 Scene、撤销/重做、保存重开、导出或统一预览。只测函数返回值不足以通过。涉及同步另检查没有无意义内容变更。

| 编号 | 用户操作序列 | 通过条件 |
| --- | --- | --- |
| T01 | 加素材→拖动→撤销→重做→重开 | 坐标一致，无重复对象 |
| T02 | 多选→移动旋转→保存 | 所有目标正确提交一次 |
| T03 | 多选增减→批删→撤销 | 集合完整，未选对象不受影响 |
| T04 | 组合→进入→编辑子层→退出 | 面板和画布目标一致 |
| T05 | 选组合根→解除组合 | 操作可达，外观与层序不变 |
| T06 | 复杂效果组合→解组→撤销 | 保留效果或明确禁止，无静默丢失 |
| T07 | 锁定子层→拖组/批改/删除 | 所有入口统一拒绝 |
| T08 | 隐藏锁定笔迹→叠加擦除 | 只擦可编辑可见笔迹 |
| T09 | 锁定最后笔迹组→继续写 | 新笔迹可见且原组不变 |
| T10 | 移动→空操作→撤销 | 一次即撤销移动 |
| T11 | 撤销→取消面板→重做 | 重做仍有效 |
| T12 | 滑条连续拖动→撤销 | 一步恢复拖动前 |
| T13 | 输入中文→选词→换行→返回 | 无漏字重字，末次输入落盘 |

| T17 | 胶带取多段→改端头→保存 | 来源区间可追溯，宽度规则一致 |
| T18 | 纸张改尺寸方向→撤销 | 内容和物理比例按预览恢复 |
| T19 | 拖出画布松手→继续操作 | 没有悬挂手势和事务 |
| T20 | 书写中双指→缩放→继续写 | 手势转换无误画和跳变 |
| T21 | 图片失败→重试→删除→旧请求完成 | 恢复正确且已删对象不复活 |

| T23 | 保存中断网→返回→重开→联网 | 本地修改保留并可重试 |
| T24 | 无修改打开→加载高清→返回 | 不生成内容事务或冲突副本 |
| T25 | AI 导入→手改→AI 接续 | 同一合同、锁定与尺寸规则一致 |

| T27 | 翻片开合和口袋抽看 | 临时观看不产生保存与冲突 |
| T28 | 翻片背面编辑→重开→导出 | 背面资源完整且能再次编辑 |
| T29 | 勾选填写→撤销→只读查看 | 状态持久与权限正确 |
| T30 | 循环打开关闭大作品 20 次 | 资源释放，内存不持续无界增长 |
| T31 | 同一作品两设备修改并保存 | 自动保留两份，资源完整，无字段排解 |
