# 纸张预设与无本例参考的创作测试

本轮接续标题、正文、装饰研究，纠正上一轮“有原作参考和人工逐例修复”不能作为自主创作证据的局限。私人图片、请求记录与结果位于 `验收归档/运行记录/双难度教程研究-2026-11-23/blind-paper-study/`，不提交到仓库。

## 纸张能力

在现有 `graphic.add` / `layer.update` 的 `style` 下新增 `paperSurface`，不新增独立工具。`{kind:"torn"}` 是直接可用的撕边纸预设：默认 intensity 0.45、seed 17，包含细微纤维与真实透明的非周期纸边。`matte`、`fiber` 保留直裁边；null 清除效果。颜色继续由 fill 决定，不强制米黄或留白。intensity 0 可保留撕边而关闭纸纹。预设不代表实体材料、不改变材料库存。

纸纹和撕边以物理尺度生成，种子可重复，不使用外部图片或白色遮挡假撕边。Scene、SVG 缩略图、Fabric 编辑器和 PNG 导出共用效果；保存保留参数而非展平图片。带质感的图形在 Fabric 使用 SVG 图像投影，数据仍是可编辑图形。透明区域、参数清除、JSON 持久化、实际渲染、渐变/描边组合与浏览器画布导出一致性均有回归。

固定构图对照只改旧 D143 的两块题签：与背景协调的灰蓝底色、撕边预设与轻阴影。图片明确标记为人工设置参数的渲染对照，不是无参考模型创作，也没有作为盲测种子。

真实调用发现模型复制检查结果中的 `paperSurface.unitScale`，因其不是公共参数而触发原子回滚。修正检查结果只返回可直接写回的 kind、intensity、seed；内部物理缩放保持在持久数据中。回归直接把检查结果写回命令，验证不再产生该错误。没有把内部字段增加为公共别名。

## 实验条件

- 五例 D143、D146、D153、D158、D162；每例完整素材与精简素材两档。
- 单独创建输入目录，仅复制 TASK 与授权素材字节；重写为同一用户 intent，去掉原作研究说明、专属构图指令、原文、参考文件与原 overview，素材总图重新生成。
- 无参考组从空白画布开始，不载入旧受指导结果。成图阶段只接续本轮自身的打底，种子及 SHA256 记录可核对。
- 禁止专属 stage-notes 和环境附加指令；关闭 search_references、Skill 图片与方法示意图。仍可读共用 Skill 文字、查询工具、查看自身素材和自身预览。
- 同一阶段的指导全文保持一致；`input-and-import-audit.json` 检查用户 intent、阶段指导 hash、无专属备注、空白起点、参考列表和接续链。
- 原任务纸幅沿用各例的实际研究规格，并非完全相同。因此十组可以比较同一提示词下的表现，但不能称为“除了素材，所有输入变量完全相同”。D143 新版配对实验则锁定纸幅、素材、用户提示、阶段指导和工具版本。
- 打底在第一张实际预览后停止；成图阶段允许两张不同 Scene 预览，模型看自己的画面后自检修正。深度思考正常输出预算，最多 12 HTTP / 600 秒；不额外付费生成独立审美总结。预览数限制是研究停止条件，不是产品创作上限。
- 所有输出仍是阶段试作，completedWork=false；技术通过不表示审美全面通过。Skill 曾从这些教程归纳过方法，这也不是严格未见教程的泛化评测。

## 异例参考对照

D143 精简素材的初版偏浅、偏平，增加“只参考 D153 成品”的条件；不提供 D143 成品或中间图。为避免把新撕边预设的收益误归因于参考图，同工具版本下重新从空白运行 D143 无参考组，并分别继续成图。参考加载器检查 targetCase 与 referenceCase 不同，并拒绝当前案例已登记的答案 hash。

配对结果：无参考版可读、纸面更自然，但大块浅纸与主体居中的关系仍偏安静；异例参考版主动增加深浅对比、点纹、横线纸和更明确的标题/正文纸层，更接近丰富层叠。它仍有投影偏重、装饰略规则的问题。只做了一组配对，不能据此宣称跨案例参考普遍优于无参考；不能将另一案例中的素材或文案当成本次授权库存。

## 解释边界

完整素材本身携带纸纹、图案与配色，通常更容易产生丰富层次。精简档需要主动重建纸层、色差与纹样，添加纸纹并不会自动解决构图。无参考与异例参考是分别标明的条件，不能混合计算“自主成功率”。原图只由研究者用于事后对照，未回填到无参考组。

## 深度思考截断问题

D158 完整档成图首轮连续五次 length 截断，返回的 completion_tokens 为 14000、8000、8000、8000、8000；前几次全部用于 reasoning，未执行工具。恢复策略把输出额度压小并降低思考强度，导致重复消耗，最终 CREATIVE_STALLED，保留该失败目录。

适配器现对思考创作省略 max_tokens，使用服务商默认额度；截断恢复不再自动降低用户要求的思考强度。网络超时重试仍可低思考，仍受任务总截止时间约束；单次高思考等待上限提高到 300 秒，低思考 150 秒。短审查、摘要和非思考动作的独立限额不变。依据 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)，思考模式默认 64K，max 强度默认 128K；更大上限不代表每轮都会用满。相关回归验证思考请求不带人为小上限、恢复保留高思考、短动作原额度和剩余时间约束。

只对失败的 D158 完整档从相同无参考打底重试，用户与阶段提示词不变，不加案例指导。修复前后运行分开存放；本轮仅这次重试验证了新的输出额度策略，不能把整批视为完全同一模型预算的统计试验。

## 最终结果与验证

共 25 次阶段运行、98 次真实 HTTP 请求、36 张阶段预览。API 返回的 total_tokens 累计 2,859,833（含输入与缓存命中，不等于费用或全部新增输出）。五例双难度均已获得打底与成图；其中 D158 完整档首次失败，单独重试成功，保留失败记录。另有 D143 同版本无参考/异例参考配对。

D158 重试 6 次请求、约 272 秒，首轮输出 20,620 tokens，其中思考 20,083；六轮均未截断。这验证了之前的小额度确实会阻塞工具执行，并不表示更大额度自动提高画面质量。

目视检查：D146 完整档的黄蓝层次和标题较好；D143、D153 精简档仍偏浅；D158 投影较重；D153 完整档和 D162 精简档存在局部文字遮挡。预设解决纸边与表面问题，没有把所有布局变成合格成品。逐例记录在 visual-review.json。

验证：npm test 为 2058 通过、1 跳过、0 失败；npm run test:ui 通过（7 个视口）。随后新增的审计测试及相关纸面测试 14 项通过，思考恢复相关测试 25 项通过。实际 Chromium Fabric 与 PNG 的平均通道误差约 0.0024，保存后仍可编辑。输入及项目导入审计通过。
