# 数据格式与升级约束

当前正式结构：浏览器本地六表 IndexedDB v1；云端 Supabase RPC/修订 v1；备份中的数据结构版本 v1。`.shiyepwa` ZIP 容器是 version=2（仅指容器），数据内容采用独立 `schemaVersion=1`。

新版本必须先具备：可恢复备份、纯函数迁移、完整数据验证、隔离数据库实测、异常回滚，然后才能使用更高 schemaVersion。旧客户端遇到高版本直接拒绝，而不是默默丢字段/清库。

当前只注册已上线的数据结构 v1；**尚未执行任何生产结构迁移**。不要把“支持版本编号”描述成“所有未来版本迁移已完成”。

若将来新增具体数据字段：先在独立 fixture 使用 migrateDetachedSnapshot，确认旧快照未被就地修改，旧图片字节不变，再提交数据库及前端迁移 PR 并进行隔离恢复测试。
