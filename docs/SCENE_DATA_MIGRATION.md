# Scene 数据版本升级：一次性离线转换，不保留旧运行时模型

正式运行的拾页只接受 `sceneVersion: 2` 和递归 `layers`。对于旧数据，**先导出并保存完整原始备份，再使用与版本相关的离线转换工具处理**；不要在编辑器、AI、渲染、同步模块里永久保留 v1 自动迁移。

## 本次 Scene v1 → v2 操作

1. 在测试版「作品」找到已隔离的旧版作品，使用「导出旧版原始备份」下载 `拾页旧版作品原始备份-*.json`。请确认文件可被正常打开，另存一份到安全位置。
2. 在包含拾页源码和 npm 依赖的可信本地电脑执行：
   ```bash
   node scripts/migrate-project-data.mjs --input 旧版备份.json --output ./migrated-scenes
   ```
   可通过 `--assets assets.json` 传入与旧素材 ID 对应的**真实素材库元数据数组**，立即校验物理尺寸、裁剪和库存；如果没有传入，拾页应用在导入时依然会严格验证，任何不合法的素材都不能导入。
3. 检查 `migrated-scenes/migration-report.json` 中的 `accepted`、`rejected` 和输出 SHA-256；不应忽略失败项。转换器输出一个或多个 `*.shiye-scene.json`，不覆盖原文件、不上传 COS/Supabase，也不会删除原作品。
4. 通过拾页「导入可编辑 Scene JSON」导入新场景。检查实际画面和素材位置，确认云端已同步、关闭并重新打开仍能正确编辑。
5. **只有上述全部确认后**，才单独考虑清理旧版云端记录或原始 COS 文档。不要同时在数据库中直接修改旧数据，也不要自动清空「最近删除」和本机待同步队列。

该转换工具不在 `src/` 应用运行时路径中；其输入是用户主动导出的备份，不是在线登录自动迁移，因此不会在新版程序里同时维护两套场景数据。

## 今后的重大结构变更

每次不兼容修改分别提供 `scripts/migrate-<旧版>-to-<新版>.mjs`，至少满足：只读输入、独立目标目录、单条失败隔离、严格校验、幂等 ID、原始字节哈希与结果清单；在测试账号的备份副本上实测之后再考虑批量回写。保持新版本核心存储、创作、渲染只识别新版本。
