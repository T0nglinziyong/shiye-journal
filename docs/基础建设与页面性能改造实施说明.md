## 1 修改目标与执行边界

请在现有代码基础上补齐备份恢复、应用更新、页面容错、导航、缓存、全库检索、任务管理和发布验证能力。最终体验应当是：用户的数据有可靠退路，返回看过的页面能迅速继续操作，分页不会缩小搜索范围，后台工作不会拖慢前台交互。

本文件是实施要求，不代表这些修改已经完成，也不承诺软件从此不存在任何故障。交付标准是明确处理失败场景、保留恢复路径，并用可重复的测试验证。识别算法、AI 创作算法及画布能力本身不属于本次重写范围。

同步协议、作品冲突保留两份、非作品冲突自动处理、删除库存、素材使用状态、胶带偏好和创作数据迁移，以关联文档为准。本次不得另外实现一套同步队列、库存体系或冲突副本规则。基础设施通过现有领域服务及改造后的同步接口工作。

审查基线为 test 分支，HEAD 为 b06d85c32b61a28d33f59b605a82977878e94a0b，同时存在大量未提交修改。下面的代码入口是定位线索，实施前必须重新核对当前代码及 AGENTS.md，区分已完成、部分完成和仍需修改的项目，保护其他正在进行的工作。不要为了符合文档而退回已有改进。

## 2 优先级与完成条件

- P1 数据安全与可恢复性：恢复前完整校验、恢复失败不破坏旧库、更新不丢本地输入、账号缓存隔离、发布版本对应真实浏览器验证。发现实际可复现的数据丢失时，应提升为发布阻断项。
- P1 用户体验正确性：全库检索、筛选规则统一、返回页面保留位置与条件、局部异常可恢复。不能以性能优化为理由漏结果、显示旧账号内容或丢失编辑。
- P2 性能与维护：增量索引、任务取消、模块拆分、图片资源管理、样式整理、诊断持久化。这些应分批实施，以测量结果选择优化力度。

完成不是增加若干工具类。必须将真实入口接入新机制，删除或收敛旧的重复路径，补充验收证据，并说明仍然存在的平台限制。不得只通过单元测试就宣布移动端、离线或大备份场景已通过。

## 3 备份与恢复必须形成可靠闭环

### 3.1 已发现的问题与代码入口

重点检查 src/backup-archive.js、src/backup-zip-worker.js、src/backup-integrity.js、src/store.js 及 src/app.js 中的导出入口。当前导出在无 onChunk 回调时有约 192 MiB 的内存缓冲限制，而桌面文件流写入路径不受同一缓冲限制。恢复端对输入文件和解压累计量设置约 256 MiB 限制，因此存在“能导出但当前应用无法恢复”的容量不对称。

scripts/cloud-backup-cli.mjs 提供云端只读备份及验证能力，不能直接当成大型应用备份文件的恢复方案。错误提示不能把用户引向实际上不存在的恢复入口。

当前 validateRestoredRecords 主要校验六类记录、ID 重复、Blob 和部分引用，不能等同于完整作品语义校验。审查中构造的缺少画布字段且引用不存在素材的作品，以及仅保留旧云路径而无可用正文的作品，仍可通过这一层校验。这说明校验覆盖不足，不表示已复现真实用户数据被破坏。restoreBackup 后续会在事务中清空并替换相关存储，因此必须把充分校验放在替换之前。

### 3.2 必须实现的恢复流程

流程应为“读取清单 → 校验格式和资源预算 → 在隔离区解析与迁移 → 校验完整引用 → 展示预检结果 → 执行替换 → 验证可读 → 清理临时区”。原数据库在预检和取消阶段不得被清空。

预检至少覆盖版本、必填字段、ID 唯一性、素材与系列关系、作品正文、图层引用、媒体文件、隐藏素材、回收站记录，以及实际备份格式声明包含的快照和归档。哈希正确只证明文件未变化，不能证明作品可以打开。无法修复的缺失引用应阻止破坏性替换，并给出具体记录和原因；可修复问题必须给出修复规则和数量，不能静默丢弃记录。

外部云路径不能被当成已备份的文件。备份清单需要明确资源是内嵌、可验证的外部依赖，还是缺失。跨账号或跨存储服务恢复必须重新建立归属与引用；不得沿用旧账号的私有路径并宣称恢复成功。备份范围与未包含的内容应在导出和恢复界面一致呈现。

替换前提供可用的现状备份或可回滚快照。小库可使用已验证的原子事务；大库可采用隔离数据库与持久化切换标记，但切换协议必须覆盖刷新、崩溃和空间不足，下一次启动能识别未完成阶段并恢复。不得把“写了一半”当成恢复成功。恢复后的同步接入遵循关联文档，不自动全量覆盖云端。

### 3.3 容量与中断策略

明确各平台的可导出和可恢复能力，并保证同一导出方式存在可用恢复路径。大型文件优先采用分块读取、增量校验、受控批量写入和阶段进度；不能只调高限制并将整个压缩包及解压结果同时放入内存。

保留目录穿越、重复条目、解压总量、单文件大小、文件数量和压缩炸弹防护。取消、Worker 退出、空间不足、损坏文件都应终止临时任务并保留旧库。错误信息区分格式问题、资源缺失、容量不足和平台不支持，提供实际可执行的下一步。

## 4 应用更新与离线可用性

src/app-update.js 已有等待本地 flush 和 busy 判断，src/app.js 中相关 busy 条件主要覆盖导入与 AI 工作。仍需统一审查素材表单、系列表单、设置、待确认照片等尚未进入持久化存储的输入。现有防护不能直接视为覆盖全部编辑入口。

建立统一的本地脏状态登记与草稿持久化接口。表单、编辑器、导入流程声明是否有未持久化内容、如何安全落盘、能否离开。页面跳转、刷新提示、退出与应用更新复用同一判断。能自动保存就自动保存，正常切页不反复弹确认；无法保存时暂停激活更新，并明确提示原因。

public/sw.js 已有不自动 skipWaiting、多窗口限制及激活后旧缓存处理，应保留其安全意图。新增验证要覆盖两个标签页版本不同、旧页面继续请求旧资源、离线更新、安装失败和刷新中断。确保旧页面仍能取到所需版本资源，或在安全保存后协调切换，避免只更新一半。

src/react-routes.jsx 中仅用 serviceWorker.controller 判断“离线程序已就绪”不充分。界面应区分应用壳可用、所需功能资源已缓存、当前账号数据已在本地，以及作品媒体是否已下载。离线打开缺少媒体的作品要说明具体缺失，不用无限加载掩盖。

应用构建版本、数据库结构版本、缓存格式版本分别管理。普通发布不应无条件清空未变化的用户媒体；缓存格式不兼容时做定向迁移或淘汰，不能删除未同步数据。禁止新旧账号共享私有资源缓存键。

## 5 页面导航与异常恢复

src/react-shell.jsx 应补齐页面和弹层级别的 React ErrorBoundary。局部组件失败时保留应用框架、导航和已保存草稿，提供重试当前区域、返回及导出诊断入口。异步请求错误、事件回调错误与 Worker 异常需由对应任务路径处理，不能认为 ErrorBoundary 会自动捕获全部错误。

审查到的 app.js 导航主要使用内存历史。应核对浏览器 History API、系统返回键和应用内返回是否一致，统一为一个导航状态来源，避免维护两套互相循环的历史栈。刷新可恢复安全的页面位置，但 URL 不得携带私密正文或凭证；实体已删除、账号变化和无权限时应回退到可用页面。

src/react-utility-dialogs.jsx 的自定义 Dialog 与其他原生或自定义弹窗应逐步统一焦点管理、Escape 行为、背景 inert、滚动锁定、关闭后的焦点恢复和嵌套层级。存在未保存输入时复用草稿规则。中文输入法组合期间的 Escape、Enter 不应被误识别为退出或提交。

页面故障恢复和导航返回必须保留筛选、排序、页码、滚动锚点及仍有效的选择项。错误重试不得顺带重置全局数据、重建同步队列或清除缓存。

## 6 返回看过的页面应立即继续操作

### 6.1 对用户承诺的具体含义

在同一账号、数据未发生相关变化且缓存仍有效的情况下，返回访问过的列表应直接显示原内容，保留搜索、筛选、排序、分页、选择和滚动位置，不先出现全页加载动画，也不重复下载相同图片。后台可以进行轻量版本检查，不能用“后台校验”作为重刷整个界面的理由。

不能承诺所有页面永远驻留内存。设备内存不足、系统回收进程、用户主动清缓存或账号切换时允许重建页面；仍应尽量从本地恢复状态和已有资源。把“无需重复网络下载”和“组件绝不重新创建”区分开，后者不是产品目标。

### 6.2 缓存分层与生命周期

建议分为领域数据存储、查询结果缓存、页面视图状态和媒体资源缓存。轻量页面实例是否保留由测量决定，采用有容量上限的 LRU；不要长期保留所有 DOM、全部图片解码结果或多个大型 Fabric 画布。

页面身份至少包含账号、后端环境、路由与实体。查询结果键还应包含标准化搜索、筛选、排序、分页大小和数据修订标识；页码或游标属于查询分段。返回所需的视图状态独立保存，不因切换查询而意外覆盖上一份位置。退出账号立即隔离并释放对应的内存状态，持久化清理遵守未同步数据保护规则。

src/react-shell.jsx 的 renderReactPage 在缺少 preserveKey 或 key 改变时会卸载并重建根节点，部分入口已有保留机制。先核查已有 preserveKey 的覆盖范围，再决定增量修改；不得简单增加一层全页面缓存掩盖根节点生命周期问题。

保留隐藏页面时必须暂停无用计时器、观察器与高频刷新，移出焦点和辅助技术导航，确保只有当前页面处理快捷键和手势。现有全局 DOM 查询与固定 ID 也需检查，避免隐藏页面被误操作。页面释放后应注销监听器和资源引用。

### 6.3 局部更新与图片稳定性

列表项使用稳定的记录 ID，避免索引 key；对象 URL 需有生命周期和引用计数，不能每次 render 创建新地址，也不能在其他页面仍使用时 revoke。图片预留宽高或比例，缩略图升级时原位替换，避免高度跳变与滚动位移。

数据变化只失效受影响的记录、查询和统计。更新一个素材不应清空全部页面缓存；样式变化也不应重取数据。后台同步使列表成员变化时，避免正在滚动或选择期间强制跳页，可在适当时机局部合并或提示有更新。记录删除后移除失效选择，滚动锚点失效时回退到相邻项。

恢复滚动以记录锚点和偏移为主，配合布局完成后的定位，避免只记录旧像素值。主动修改查询回到第一页；从详情返回则恢复原查询及位置。打开作品可先展示本地预览，再按同步方案完成最新版本校验后进入可编辑状态；不能为了切页快而跳过编辑前的版本判断。

## 7 分页检索必须覆盖完整检索范围

### 7.1 当前行为与边界

src/library-page-data.js 的基本顺序是从 state.assets 过滤、排序，再截取当前页，因此能够搜到不在当前显示页但已进入 state.assets 的素材。它不保证检索到尚未从云端拉取到本地的新记录。分页显示和数据是否完整是两件事，界面和测试都应区分。

全库和系列内检索的字段存在差异：全库主要使用标题和标签，系列路径还涉及风格、内容与语义字段；未使用状态的判断也需统一，避免 !used 与显式 unused 产生不同结果。重点核对 src/library-model.js、src/series-contents.js 及相应页面调用。

### 7.2 统一查询契约

建立共享查询定义：检索范围、关键词、系列、素材类型、使用状态、排序、分页参数。明确可检索字段并统一标准化，至少覆盖现有标题和标签；已结构化且适合检索的风格、内容、语义标签应按同一规则纳入。此项不要求新增 OCR 或图片向量搜索。

查询顺序必须是“在完整可用数据集上限定范围与筛选 → 匹配关键词 → 稳定排序 → 计算总数 → 分页”。排序增加 ID 等确定性次级键，处理缺失时间、空字段和重复标题，避免页间重复与漏项。使用状态从统一领域规则获得，不能重新引入库存数量。

搜索保留当前筛选时，要清楚展示筛选条件和结果范围，并提供清除筛选入口。全库、当前系列与当前选择范围不能悄悄混用。结果为空时区分“当前筛选无结果”和“本地数据尚未完整可用”。离线只保证已在本地且可检索的数据。

中文组合输入期间不启动破坏性的重置或导航。输入框立即响应，查询可短暂防抖；Worker 或异步搜索附带查询序号，旧结果不得覆盖新结果。修改关键词、筛选或分页大小时重置页码并重新计算总数，删除导致页码越界时回到最后有效页。

未来若采用服务端分页，搜索必须下推到整个授权数据范围；不能先拉一页再 filter。筛选、排序、结果总数与游标需要一致语义，并处理查询中数据变化。不要为了支持全库检索下载所有原图，检索仅需要索引字段。

## 8 数据查询与前台性能

分页目前主要限制 DOM 数量，未必限制每次筛选和排序的计算量。library-page-data、library-model 与 series-contents 应共享领域选择器，减少反复扫描数组、重复标准化文本及系列封面查找。索引以 ID 关联记录，按变化增量维护，不能成为另一套独立真相来源。

优先缓存稳定的文本标准化结果、排序比较器和系列关系。缓存必须有明确失效条件，覆盖新增、编辑、删除、恢复、账号切换及同步落地。不要把整个对象 JSON 序列化作为每次 render 的缓存键计算。

先测 1000、5000、10000 条素材规模，分开记录计算、DOM、图片解码和网络耗时，再决定使用 Worker、列表虚拟化或服务端检索。列表虚拟化必须保持选择、键盘焦点和返回定位正确，不应仅为减少节点而引入滚动跳变。

src/app.js 静态依赖较多，但现有部分功能已懒加载。应分析首屏实际依赖和请求瀑布，再拆分低频管理、备份或重型工具模块。不能用整个 dist 的大小代替首屏体积，也不能把全部模块预加载称为优化。闲时预取必须避让前台，且按离线功能声明确保必要模块可用。

## 9 后台任务与批量操作

src/classification-queue.js 已有优先级和并发限制，但取消与 AbortSignal 能力需要补齐。只忽略过期结果不能停止已经占用网络或计算资源的任务。统一任务接口应包含 ID、所属账号、来源页面或业务、优先级、取消信号、进度、超时和失败原因。

排队任务取消后及时移出；运行任务尽可能中止请求或 Worker 计算。不可中止的阶段必须阻止过期结果写入当前状态。页面销毁不一定取消用户主动发起的持久任务，但应解除视图订阅；账号切换必须禁止旧任务结果写入新账号。

前台操作优先，后台有公平调度避免永久饥饿。重试有次数、间隔和幂等约束，离线时不高频空转。通用调度层不另行接管同步协议，使用适配器复用已有同步队列。

批量操作以明确的 ID 快照执行，区分“当前页”“已选择”“全部搜索结果”，显示数量和范围。重复点击不得启动重复任务。部分失败时展示逐项结果，只重试失败项；跨页选择不能在翻页时悄悄丢失。撤销仅在不会覆盖后续修改时提供，涉及删除与同步时复用领域删除规则。

## 10 存储管理与诊断

提供面向普通用户的存储说明，区分缩略图、可重新下载的文件、已同步原图、本地草稿、未上传媒体和备份临时文件。现有 storage-usage-ui.js 的管理用途不能直接替代用户存储管理体验。

允许安全清理可再生缓存，提供预计释放量与结果；未同步数据、活动编辑依赖以及唯一原件必须受保护。根据引用和使用状态清理，不能仅凭时间或文件名。浏览器空间估计不可用时显示未知，不能显示为零；空间不足时停止扩张并保留数据恢复入口。

src/runtime-diagnostics.js 当前主要保存最多 80 条内存记录，刷新后会丢失。增加有大小上限和 TTL 的本地诊断环，覆盖最近版本、关键操作阶段、请求关联标识和失败类别，避免高频日志拖慢交互。记录需要脱敏，不包含正文、图片、令牌、完整私有 URL 或其他账号信息。

诊断导出应同时携带构建标识和相关能力版本。为发布构建保存可追溯的内部 source map，使堆栈可定位到对应提交；不要公开包含敏感内容的调试产物。提供用户主动导出入口，不因本次改造自动增加外部遥测上传。

## 11 样式与模块边界

逐步收敛多份覆盖样式和散落的 !important，建立颜色、间距、字号、弹层层级等基础变量，明确组件样式归属。先处理影响交互和布局的冲突，不进行没有验收依据的全量 CSS 重写。

以页面、查询、资源、任务、导航、诊断等职责建立清晰接口。底层服务不直接查询 DOM，页面不自行复制数据库和同步规则。迁移按真实用户路径逐步替换，并删除已无调用的旧实现，防止出现“新框架接入了一半”的长期状态。

## 12 实施顺序与发布验证

第一批完成现状清单、恢复预检与安全替换、更新草稿防护，以及可复现的失败用例。第二批统一查询契约、导航状态和资源缓存，再改造返回页面体验。第三批补齐任务取消、诊断、容量管理和低频模块拆分。样式治理随页面迁移推进。

每批保留独立可回退的提交，不把数据迁移、页面缓存和构建拆分混在一个无法定位问题的大改动中。涉及持久化结构时提供前后兼容规则和迁移失败策略；不能通过清空用户数据完成升级。

现有 test:ui 使用 happy-dom、fake-indexeddb 等测试替身，适合逻辑验证，但不能代替真实浏览器。审查时 interface-browser.yml 主要由目标为 test 分支的 PR 与手工入口触发，应补齐实际发布路径的验证，确保发布 SHA 就是验证过的 SHA，尤其覆盖直接提交路径。

真实浏览器至少覆盖 Chromium 和 WebKit 的主要流程；iPad 的内存、触摸、Pencil、系统回收和 PWA 行为仍需实际设备验证。记录设备、系统、数据规模、网络条件和构建标识。未测试的平台应如实列为限制。

建议将温热列表返回的点击到有效内容绘制 p95 不超过 100 ms 作为目标，在明确的目标设备上测量后确定门槛，不作为所有设备的绝对保证。滚动重点检查长任务与丢帧，50 次页面往返后内存不应持续单调增长。缓存命中测试允许轻量后台检查，但不允许相同媒体重复下载或全页闪白。

## 13 必须执行的验收用例

以下用例需记录通过、失败或未验证及原因。单元测试验证纯规则，集成测试验证存储和状态流，浏览器测试验证真实操作与刷新恢复。

- B01 正常备份恢复：素材、系列、作品及媒体数量正确，代表性作品能实际打开并渲染。
- B02 损坏与缺失：哈希错误、缺素材图层、缺作品正文、错误云路径被预检识别，原库不变。
- B03 恢复中断：取消、刷新、Worker 退出、空间不足均可重新进入，旧库或已确认切换的完整库可读。
- B04 容量边界：分别测试输入与解压总量的阈值两侧，以及桌面大文件流导出后的实际恢复路径。
- B05 备份安全：目录穿越、重复条目、超量条目及异常压缩比被拦截，临时资源可回收。
- B06 账号迁移：跨账号恢复不引用旧账号私有资源，不自动覆盖不相关云数据。
- U01 未保存表单遇到更新：自动保存成功后更新，保存失败时保留表单并阻止激活。
- U02 多标签页版本切换：旧页面资源仍可用或安全协调更新，没有半更新和输入丢失。
- U03 离线启动：应用壳、功能模块、本地数据和图片的缺失分别正确呈现，不误报全部就绪。
- N01 三种返回：应用返回、浏览器返回、移动端返回行为一致，无历史循环和重复跳转。
- N02 刷新与失效实体：可恢复页面状态，删除或无权限实体有正确回退，URL 无敏感内容。
- N03 局部渲染故障：区域可重试，其他导航可用，草稿与诊断保留。
- N04 弹窗操作：键盘焦点不逃逸，关闭后恢复焦点，嵌套层级、滚动锁定和中文输入正常。
- P01 列表往返：从深页进入详情再返回，查询、页码、选择及锚点保留，无全页加载闪烁。
- P02 媒体复用：多次进入同一页面不重复下载未变化的媒体，切页不提前释放仍在使用的对象 URL。
- P03 局部变化：编辑一条素材只更新相关视图，删除锚点与页尾数据后能正确定位和修正页码。
- P04 缓存淘汰：达到容量后释放旧实例，返回可从本地重建；50 次往返无持续泄漏或监听器倍增。
- P05 账号隔离：切换账号后不出现上一账号的页面、搜索结果、图片或迟到的任务结果。
- S01 跨页命中：只在后续页放置唯一关键词，在第一页搜索也能命中，数量与分页一致。
- S02 查询一致：全库与系列在相同范围和条件下，标题、标签、结构字段与使用状态规则一致。
- S03 查询竞态：快速输入、删除、切换筛选及中文组合输入后，只显示最后一次有效查询结果。
- S04 排序边界：同名、同时间、空字段、大批新增删除均无页间重复、漏项或越界空页。
- S05 数据不完整：离线或云端尚未拉取时准确提示本地范围，不能宣称已检索全部远端数据。
- T01 任务取消：排队任务移除，运行任务中止或隔离结果，返回页面不重复提交原任务。
- T02 批量部分失败：范围和数量明确，只重试失败项，重复点击幂等，撤销不覆盖后续编辑。
- D01 缓存清理：可再生资源被清理，未同步媒体、草稿和活动引用保留，空间不足可恢复。
- D02 诊断导出：刷新后仍有最近失败阶段，版本可追溯，报告不含凭证和私有正文。
- R01 发布门禁：实际发布 SHA 通过所需浏览器流程，失败能阻断发布；回退不破坏持久化数据。
- R02 性能基线：三档数据规模记录冷启动、温热返回、检索、滚动和内存，与修改前同条件比较。

## 14 交接成果要求

实施者应交付实际变更清单、删除或统一的旧路径、数据兼容说明、测试结果、性能对比和剩余限制。每项未完成要求要说明原因及影响，不能只写“优化完成”。
