# 拾页创作 Skill

这里有 8 个正在使用的专题。开局只给 Agent 专题名称及触发描述；它看到实际素材与画面后，按当前问题调用 `read_skill`。优先读能改变下一批编辑决策的一个专题，避免把全部教程塞进上下文。方法 ID 在工具库中保持稳定；单个基础图形和普通字效由基础命令直接实现。

| 当前环节与问题 | 读取专题 | 可选组合方法 | 典型收获 |
| --- | --- | ---: | --- |
| 选配色、判断颜色面积 | `journal-color` | 1 | 主辅色与跨页呼应 |
| 打底、图文重心、阅读路线与文字预留 | `journal-composition` | 0 | 根据真实画面试摆、预留写面并修订 |
| 纸层、胶带、裁切与透明承托 | `paper-layering` | 7 | 撕纸、开窗、穿插、分裁与点对点关系 |
| 照片、票据和杂志式图组 | `photo-story` | 2 | 复杂胶片组和可调胶片边框 |
| 标题及 H2/H3 需要组合字效 | `journal-lettering` | 13 | 字群、背景与字效配方 |
| 正文题材、段落或功能记录 | `journal-writing` | 2 | 内容写法、记录版式与素材内书写 |
| 可调结构图形及局部图案 | `journal-graphics` | 3 | 图形参数与形状关系 |
| 接缝、边缘与内容簇缺连接 | `journal-accents` | 2 | 点缀位置、尺度和保护区 |

现有工具库只保留 30 个可调用方法。原来的 17 个单步图形、图案及普通字效改用基础命令；13 个按固定坐标摆放素材的配方移除，因为它们不理解内容或画面重心。24 种有用的变化形式收进对应方法的 `parameters.variant`，不再有独立方法 ID。各专题 Skill 正文直接写出该选哪种变体；`detail` 给完整参数，必要时用 `read_skill level=detail,variant=...` 读取该效果的示例。开窗复用、穿插、轨迹撕纸等难以用基础命令稳定拼出的封装仍保留。

构图 Skill 主要教观察、试摆和视觉审查，不要求调用固定布局配方。`overview` 给判断原则和 30 个入口中的本专题部分，`methods` 每页最多八个摘要，`detail` 才给参数、示例和可用示意图。单次摆放、普通星形、阴影或点阵直接用基础命令；不要为了使用方法而使用方法。风格变体、来源字段与原始研究笔记保存在 `creative-agent/research/`，不作为 Agent 的独立 Skill 正文。

## 示意图

每个专题最多附两张已目视检查的 PNG。`illustrations.json` 保存作者、公开来源、观察范围、说明、内容哈希和审核状态；第三方原图与裁切图保存在仓库外的本机资料库，不随前端发布或素材包导出。

后台设置 `SHIYE_CREATION_ILLUSTRATIONS_DIR` 为已核对的图包目录。加载时验证目录边界、文件大小、PNG 尺寸和 SHA256；配置了图包但文件缺失或损坏会报错。未配置时目录明确报告图片不可用，仅加载文字，不声称看过示意图。

开局只给模型专题目录，不发送整套 Skill 或示意图。不要求 overview → methods → detail 逐级打卡；已知方法可直接读 detail。`overview` 返回专题正文及已配置的专题示意图；`methods` 只列最多八个方法的用途和参数名，不传八张图；`detail` 返回单个方法的完整参数、示例及其可用示意图。图片以真正的数据发送，而不只给路径。没有配置专题图包时，专题只返回文字；仓库内置的方法图仍可在 `detail` 时发送。同版本、同层级重复读取不重复附图，但始终返回文字、准确参数与刷新了事务编号和 Scene 版本的示例；历史被压缩后仍能恢复所需合同。作者、URL、校验哈希等来源字段保存在 `illustrations.json` 供审查，模型只看到简短图片说明。教程图不能当成本次来源素材或最新作品预览。

## 继续研究与图像提取

使用 `scripts/extract-tutorial-illustrations.py` 从已下载原图或视频截图提取内容区域。输入 JSON 包含 `illustrations` 数组，每项须有 `id`、`file`、`sourceURL`、`author`、`title`、`observation`、`caption`；`crop` 为 `[x,y,width,height]`，默认像素，`units: normalized` 可使用比例。

原图优先。截图应避开翻页动画、播放按钮、导航与评论；保留作者标记。导出后逐张检查内容和裁切边界，核对来源页码或视频时间，再标记 `reviewed: true`。没有完整阅读的视频不能写成已完整观看。自动裁切工具不会替代目视检查。

倾斜纸面使用 `quad` 替代 `crop`：四点依次为阅读方向的左上、右上、右下、左下，工具据此做透视矫正并排除纸外背景。需要转正时用 `rotateClockwise: 90/180/270`。已知纸张比例可指定 `targetSize`；否则仅从可见边长估计输出比例，不能宣称测得真实尺寸。无法看到完整纸面、手部遮挡或曲面变形严重的帧，应改用其他图或只保留明确的局部步骤，不合成缺失内容。处理参数及逆映射写入来源记录，原图不覆盖。

新增 Skill 应明确触发条件、实施步骤、预览检查与不适用情况；不要为单个成品制定通用比例。原教程方法和本项目工具映射分别说明。验证时至少覆盖不同尺寸、素材数量、文字模式与实际工具限制，再判断是否改善创作。

## 工具表述约定

Skill 负责适用条件、选择理由、实施思路、看图检查与停止条件。基础操作通过 `creation_help({topics:["准确操作名"]})` 查询；方法通过 `read_skill({name,level:"detail",methodId})` 取得准确参数与完整示例。不要手写省略必填字段的伪完整调用，也不要把 CLI 的 `describe` 当作 Agent 工具。需要专题内提到的扩展工具时，用 `creation_help({topics:["工具名"]})` 展开；同一任务中保持可用。
