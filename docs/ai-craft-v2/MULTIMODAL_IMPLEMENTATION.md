# GPT 多模态素材创作：一次交付实现

实施基线：main `7ad4f904cc5b5787415553b644f9d8a2b750ee93`，续接 PR #2。本文描述代码实现，不把模型审美、实体设备或跨设备字体一致性视为已验收。

## 使用路径

用户只需一次导出素材任务、一次取得 GPT 最终结果、一次导入。GPT 可以在这次工作内看图、提出局部选区、编译、渲染并修正，无需让用户反复导入导出。未提供语义标注也可创作；素材详情的区域标注只是可选的人工保护/精确选区工具。

新安装的 API 默认采用 OpenAI / GPT-4.1、多模态输入及交付前视觉复核。已有提供商、地址、模型、密钥、显式禁图设置均保留。无提供商标记的旧密钥仍按旧 DeepSeek 默认处理，绝不把旧密钥静默发到另一家。网页 ChatGPT 任务不依赖 API 密钥。文字/工具模型的图片输入与独立图片生成接口仍分开，生成的 PNG 不冒充可编辑真实素材。

新搭配会话采用“AI 自主加工”，但从本地恢复的旧选择和逐件“保留完整”仍优先。纸张/胶带可自由使用已经实现的工序，其余类型默认轻度裁剪。需要从照片、贴纸抽取较小局部时应明确选择自由拆解；不能靠提示词覆盖已有授权。

## 已接通的代码

| 环节 | 实现 |
|---|---|
| 看图选区 | `craft-vision.js`，同一计划中的 observations 表达词句、图案、纹理、空白等局部。来源版本与实际提供的图像必须匹配；观察仅是模型建议，不变成用户确认或写回素材库。 |
| 原子计划 | `apply_craft_plan` 支持 whole、毫米矩形、已确认区域、本次看图区域及显式多边形取材；与已有边缘加工、图文及关系一次提交。任一子步骤失败回滚整份计划，命令号重放不重复添加。 |
| 正负形与余料 | polygon-clipping 有界布尔核；按原素材毫米空间核验交集、洞、窗口越界和分离片。父片显式消费，子片保留谱系；可编辑余料进入备选，过小碎屑/显式废料记账占用，不被静默重复使用。 |
| 局部穿插 | 两个真实开孔 + 足够孔宽 + 一根平直纸条的有限宏；一个实体在多个显示片段中前后穿插，保持同一位置/裁片/尺寸，库存只计一次。不是任意三维折叠或无孔的循环 z-index。 |
| 文字镂空 | `runtime/glyphs.cjs` 从执行环境已有且有权使用的本地字体生成数值轮廓，支持连接桥。缺字报错，输出不含字体文件；轮廓用于 cut_shape/remove。字腔或断开部分需桥接或显式分件，不能白色覆盖伪造。 |
| 统一成图 | `scene-renderer.js` 被应用 PNG/PDF 快照与任务包的自包含浏览器页面复用。等待实际字体加载、材料图像解码，保持源 crop、翻转、洞和局部显示。缺图明确失败而非输出误导预览。 |
| 网页运行工具 | 新包附同源 validate/preview/pack、工艺合同、来源快照、CRAFT_GUIDE、glyphs。preview/pack 额外生成 `output/画面预览.html`，可在浏览器里导出 Canvas PNG。SVG仍是构图级备选；结果 ZIP 不把外部可执行 HTML 当工程入口导入。 |
| API 交付前复核 | 最终实际渲染图发给已配置的视觉模型；最多两次检查，和创作/格式修复共用总请求预算。允许受限且原子化的局部修正后重渲染；保存失败不吞掉，取消不再执行新修正。 |
| 版本与手改 | 三代旧离线合同保持原指纹；新多模态能力单独声明。完整素材/标定/库存/区域/起始场景冻结，后续有变化不使用旧条件。生成前已经存在的用户接管图层也保护，不能仅以“未锁定”判定可覆盖。 |
| 编辑和往返 | 原生包临时撤销栈不复活；活动草稿、持久存档、对象/关系/局部显示引用正确映射。复合轮廓、五类参数化边缘可在统一加工面板中编辑。 |
| 选择与缓存 | 合并本分支已有的更多操作 toggle、三列菜单对齐、子菜单/Esc/外部关闭、暖缩略图、封面子树与内容版本缓存、账号和图像失效；展示缓存不替代可编辑原稿或同步队列。 |

## 单次计划示意

```json
{
  "format": "shiye-craft-plan",
  "version": 2,
  "commandId": "story-one",
  "baseSceneHash": "读取任务 source.baseSceneHash",
  "observations": [{
    "id": "word-block", "asset": "读取素材alias", "sourceRevision": "读取sourceSnapshots版本",
    "kind": "text", "label": "图片中实际可见的词句", "boundsRatio": [0.1, 0.1, 0.4, 0.3]
  }],
  "pieces": [{
    "id": "word-piece", "asset": "同一素材alias", "sourceRevision": "同一来源版本",
    "extraction": {"type": "observed_region", "observationId": "word-block"},
    "centerMM": [80, 65], "rotationDeg": -8
  }]
}
```

该片段只是字段示意，哈希占位符不是可直接执行的任务。真正合同由代码生成，不维护第二份漂移的手写 schema。返回 envelope 的 source 必须保留原任务。

## 明确边界

1. GPT 的看图区域不是精确分割证明；看不清时保留更宽边界/整件，不能声称人工确认。
2. 便携预览使用任务缩略图，应用最终输出使用账户原图。同源 Canvas 算法并不保证不同设备的系统字体文件完全相同；报告字体环境，不伪造 fontSetVersion 或“跨设备逐像素相同”。离线结构编译采用确定性的文字高度估计，防止同一 recipe 因 DOM 环境不同改变结构。
3. 图片模式只能获得不可逐层编辑的画面，不能证明现实材料大小与数量；严格材料守恒应使用可编辑计划模式。
4. 两孔穿插只验证当前平面模型所需的开孔与纸条宽度，不宣称任意复杂折叠可制作。人工移动后不强制把对象拉回原处。
5. 工艺数量、填充率和零重叠不作为审美门槛，whole 与留白合法。
6. 本批不处理无关账号/COS/同步数据库迁移；没有改私人素材或 DNS。

## 测试和发布

先运行 `npm test && npm run test:ui` 和 Python 转换测试；运行实际 Chromium 的 craft-browser、presentation-browser、craft-multimodal-browser。多模态浏览器用合成图片验证：一次视觉选区+两孔穿插计划、三个实体/五个显示片段、编辑器选中及加工面板、刷新保留、原素材不改、便携与应用 Canvas 的孔内/孔外像素和场景哈希。

最终结果记录在 `DELIVERY_RESULTS.md`（由实际 CI 完成后生成），而不是把本文测试要求当作测试成绩。实体 Safari/iPad/Pencil 和真实付费 GPT 审美需要独立标注，不能从 mock 或 Chromium 模拟视口推断。

## 迁移与回滚

不迁移数据库、不清缓存和 outbox、不强改旧参数；新作品仍是版本化可编辑数据。新计划能力只有重新导出的任务包才有。回滚前保留新任务与作品 ZIP；旧前端不认识新工艺/局部片段，不能用旧版静默删字段作为兼容方案。更新既有 Vercel 项目，只接受精确提交的 Git 自动部署和固定别名核对。
